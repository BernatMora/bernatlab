📖 Resum del capítol

La idea clau

Un sistema que no s'actualitza es un sistema vulnerable. Un sistema que s'actualitza MAL pot deixar-te amb serveis caiguts, dades corrompudes, o problemes de compatibilitat. La gràcia de l'actualitzacio segura es actualitzar AMB CONFIANCA: saber que passa, tenir plan B, i poder tornar enrrere si cal.

Per que es vital actualitzar

  1. Seguretat: les vulnerabilitats es descobreixen constantment.
  2. Estabilitat: les noves versions corregeixen bugs que poden fer-te caure.
  3. Funcionalitats: nous serveis, millor rendiment.

Apt: el gestor de paquets

sudo apt update
apt list --upgradable
sudo apt upgrade -y
sudo apt full-upgrade -y
sudo apt autoremove -y
sudo apt autoclean

unattended-upgrades: actualitzacions automatiques

sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

Configuracio a /etc/apt/apt.conf.d/50unattended-upgrades:

Unattended-Upgrade::Allowed-Origins {
    "origin=Debian,codename=${distro_codename},label=Debian-Security";
    "origin=Raspbian,codename=${distro_codename},label=Raspbian-Security";
};
Unattended-Upgrade::AutoFixInterruptedDpkg "true";
Unattended-Upgrade::MinimalSteps "true";
Unattended-Upgrade::Remove-Unused-Dependencies "true";
Unattended-Upgrade::Automatic-Reboot "false";
Unattended-Upgrade::Automatic-Reboot-Time "03:00";

Watchtower: actualitzacio automatica de contenidors

  watchtower:
    image: containrrr/watchtower:latest
    container_name: watchtower
    restart: unless-stopped
    user: "0:0"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    command:
      - '--label-enable'
      - '--include-stopped'
      - '--schedule'
      - '0 0 4 * * *'  # Cada dia a les 4:00 AM

Label per permetre l'actualitzacio:

services:
  homeassistant:
    image: homeassistant/home-assistant:stable
    labels:
      - "com.centurylinklabs.watchtower.enable=true"

Dependabot: actualitzacio dels teus repositoris

Configuracio a .github/dependabot.yml:

version: 2
updates:
  - package-ecosystem: "docker"
    directory: "/"
    schedule:
      interval: "weekly"
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"

Blue-Green deployment

Tecnica per actualitzar sense temps d'inactivitat. Tens dos entorns (blue i green), un esta actiu i l'altre es la nova versio.

# Desplega la nova versio amb port diferent
docker run -d --name servei-green -p 8081:80 servei:v2
# Comprova
curl http://localhost:8081
# Atura vella, arranca nova al port original
docker stop servei-blue
docker rm servei-blue
docker run -d --name servei-blue -p 8080:80 servei:v2
# Neteja
docker stop servei-green
docker rm servei-green

Rolling Updates: mes realista

  1. Abans: fer backup.
  2. Llegir CHANGELOG: que canvia?
  3. Provar en local si es pot.
  4. En hores de baixa activitat.
  5. Un sol servei a la vegada.
  6. Verificar: curl, grafana, logs.
  7. Si algo va malament: rollback.

El fitxer CHANGELOG

SEMPRE mira el CHANGELOG abans d'actualitzar. Busca "BREAKING" o "breaking change".

v2.5.0 (2026-05-01):
  BREAKING: canvi en la configuracio de xarxa
  Nova opcio: --new-feature
  Bugfix: corregit memory leak a HA

Pinning de versions

# BE
image: homeassistant/home-assistant:2024.5.0

# MAL
image: homeassistant/home-assistant:latest

# Rang: sempre la ultima 2024.X
image: homeassistant/home-assistant:2024

Estrategia de versions

  • MAJOR (v1 -> v2): canvis incompatibles. Cal planificar.
  • MINOR (v1.5 -> v1.6): noves funcionalitats, generalment compatibles.
  • PATCH (v1.5.3 -> v1.5.4): correccions. Sempre aplicar.
  • Sempre actualitza PATCH.
  • Regularment actualitza MINOR (cada 1-3 mesos).
  • Amb molta cura actualitza MAJOR (1 cop l'any, amb proves).

🛠️ Exercici pràctic (30-45 min)

Configurar actualitzacions automatiques de seguretat, instal·lar Watchtower i practicar un rollback.

Pas 1: Configura actualitzacions automatiques del sistema (10 min)

sudo apt update
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
sudo nano /etc/apt/apt.conf.d/50unattended-upgrades
sudo unattended-upgrades --dry-run -d

Pas 2: Configura notificacio per correu (5 min)

Afegeix Unattended-Upgrade::Mail "bernat@exemple.com"; a la configuracio.

Pas 3: Instal·la Watchtower (10 min)

Afegeix el servei watchtower al docker-compose.yml amb el schedule. Puja amb docker compose up -d watchtower.

Pas 4: Marca els teus serveis per Watchtower (5 min)

Afegeix label com.centurylinklabs.watchtower.enable=true als serveis stateless. Deixa sense label les bases de dades.

Pas 5: Comprova que Watchtower funciona (5 min)

docker logs watchtower
docker exec watchtower /watchtower --run-once

Pas 6: Practica un rollback (10 min)

Comprova versio actual, baixa versio antiga coneguda, atura+esborra contenidor, aixeca amb versio antiga. Comprova que funciona.

Validació

  • ☐ unattended-upgrades esta configurat i funciona.
  • ☐ Watchtower esta corrent amb schedule.
  • ☐ Has marcat els serveis adequats amb label.
  • ☐ Has deixat sense label les bases de dades.
  • ☐ Has practicat un rollback manual amb exit.
