📖 Resum del capítol

La idea clau

Tots els sistemes fallen. La diferencia entre un administrador de sistemes bo i un de dolent no es que el primer no tingui fallades, sino que SAP diagnosticar-les i arreglar-les rapid. El troubleshooting es l'art d'identificar l'arrel del problema quan tot va malament, sense perdre hores buscant a cegues.

La metodologia: divideix i venceras

  1. Definir el problema: QUE falla exactament?
  2. Recollir dades: QUAN ha passat? Desde quan? Que ha canviat?
  3. Identificar la capa: fisica, SO, xarxa, contenidors, aplicacio?
  4. Aillar la causa: que SI funciona? que NO funciona?
  5. Aplicar la solucio: nomes un canvi a la vegada.
  6. Verificar: ha tornat a funcionar? Romandrá estable?
  7. Documentar: escriu al runbook que ha passat.

Les capes del sistema (model OSI aplicat)

[7. Aplicacio]      El servei concret (HA, Grafana, etc.)
[6. Configuracio]   docker-compose.yml, .env
[5. Contenidor]     Docker engine, imatges

Comandes essentials de diagnostic

Sistema basic

uptime
top
htop
free -h
df -h
vcgencmd measure_temp
cat /sys/thermal/thermal_zone0/temp
journalctl -f
journalctl -u docker --since "1 hour ago"

Xarxa

ip a
ip route
cat /etc/resolv.conf
nslookup google.com
ss -tulnp
ping 8.8.8.8
curl -v http://192.168.1.50:8123

Docker

docker ps -a
docker stats
docker logs homeassistant
docker logs homeassistant -f
docker inspect homeassistant
docker top homeassistant
docker exec -it homeassistant /bin/bash

Recursos

ps aux --sort=-%cpu | head
ps aux --sort=-%mem | head
du -sh /var/lib/docker/volumes/
ncdu /

Eines visuals

  • htop: gestor de processos interactiu.
  • glances: monitor complet amb CPU, RAM, xarxa, disc.
  • ctop: monitor de contenidors Docker.
  • lazydocker: UI de terminal per Docker.
  • ncdu: explorador de disc interactiu.

Troubleshooting per categoria

"La RPi no respon"

  1. Ping: ping IP_RPI. Si no respon, es xarxa.
  2. SSH: si la xarxa va be, intenta per SSH.
  3. Monitor + teclat: si tampoc va per SSH.
  4. Corrent: desendolla i reendolla.
  5. Hardware: microSD o font d'alimentacio.

"Un contenidor esta exited"

  1. docker ps -a per veure tots els contenidors.
  2. docker logs NOM per veure que ha dit.
  3. docker inspect NOM per veure la configuracio.
  4. Prova: docker compose up NOM per tornar a aixecar.

"El sistema va lent"

  1. top o htop per veure processos.
  2. docker stats per veure contenidors.
  3. vcgencmd measure_temp per veure temperatura.
  4. Si la CPU es 100%, mira quin proces.

"No puc accedir des de fora"

  1. Servei corrent? docker ps.
  2. Port obert? ss -tulnp.
  3. Firewall? sudo ufw status.
  4. Port forwarding al router?
  5. DDNS apunta correctament?

"La microSD es corromp"

Senyals: errors d'I/O, sistema inestable, dmesg amb errors EXT4. Solucio: mou a USB/SSD, activa noatime.

"El contenidor fa coses rares"

  1. Atura: docker stop NOM.
  2. Logs: docker logs NOM.
  3. Entra: docker exec -it NOM /bin/bash.
  4. Processos: ps aux.
  5. Fitxers: ls -la /config/.

El concepte de "checkpoint"

Quan un sistema funciona BE, documenta l'estat. Guarda-ho a ~/bernatlab/CHECKPOINT.md amb versio de cada imatge, configuracio de xarxa, espai en disc, llista de serveis actius, etc.

Buscar ajuda

  1. Google: error especific + versio.
  2. GitHub issues: busca el projecte.
  3. Forums especialitzats: HA Community, RPi Forums.
  4. StackOverflow: nomes si es generic.
  5. ChatGPT/Claude: ajuda pero SEMPRE verifica.

Sigues especific. "No em funciona HA" no serveix. "HA 2024.5 falla al arrancar amb error 'config integration not found'" si.

🛠️ Exercici pràctic (45-60 min)

Aprendre a fer troubleshooting aplicat amb simulacions de fallades.

Pas 1: Instal·la eines de diagnostic (5 min)

sudo apt update
sudo apt install -y htop glances ncdu nethogs
htop
glances
nethogs

Pas 2: Crea un checkpoint del sistema (10 min)

Crea ~/bernatlab/CHECKPOINT.md amb: versio OS, kernel, CPU, RAM, disc, temperatura, xarxa, contenidors actius, imatges, volums, xarxes. Veure exercici.md per la plantilla.

Pas 3: Simula una fallada de CPU (10 min)

yes > /dev/null &
yes > /dev/null &
yes > /dev/null &
yes > /dev/null &
ps aux --sort=-%cpu | head
htop
killall yes

Pas 4: Simula una fallada d'espai (10 min)

dd if=/dev/zero of=/tmp/gran_fitxer bs=1M count=5000
df -h
docker system df
rm /tmp/gran_fitxer

Pas 5: Simula una fallada de xarxa (10 min)

Comprova: ping, IP, gateway, ports oberts, DNS, curl.

Pas 6: Simula una fallada de contenidor (10 min)

docker stop homeassistant
docker ps -a --filter "status=exited"
docker logs homeassistant --tail 20
docker start homeassistant

Pas 7: Practica un diagnostic complet (10 min)

Per un servei concret (p.ex. Grafana), segueix: docker ps -> docker logs -> ss -tulnp -> docker exec -> curl -v.

Validació

  • ☐ Has instal·lat htop, glances, ncdu, nethogs.
  • ☐ Has creat un CHECKPOINT.md de l'estat actual.
  • ☐ Has practicat les 4 simulacions de fallada.
  • ☐ Has fet un diagnostic complet d'un servei concret.

Resum ràpid

  1. Primer pas = definir el problema exactament.
  2. Processos = top o htop.
  3. Logs contenidor = docker logs NOM.
  4. Temperatura = vcgencmd measure_temp.
  5. Entrar contenidor = docker exec -it NOM /bin/bash.
  6. Sistema lent = identificar el proces.
  7. DNS = /etc/resolv.conf.
  8. Monitor complet = glances.
