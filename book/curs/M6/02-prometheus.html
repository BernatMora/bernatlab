📖 Resum del capítol

La idea clau

Prometheus es una base de dades de series temporals (time series database) que recull metricas dels teus serveis a intervals regulars. Es el "cervell" del monitoratge: ell pregunta "com estas?" a cada servei, guarda la resposta amb marca de temps, i permet fer consultes com "quina ha estat la CPU mitjana de la RPi aquesta setmana?".

Que es exactament una metrica?

Una metrica es un valor numeric associat a un instant de temps. Per exemple:

  • cpu_usage_percent{host="rpi", core="0"} 42.5 @ 1716000000
  • memory_free_bytes 1530000000 @ 1716000000
  • docker_container_up{name="homeassistant"} 1 @ 1716000000

Prometheus guarda milers d'aquestes "mostres" i tu pots fer consultes tipus PromQL:

# CPU mitjana dels ultims 5 minuts
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# Contenidors caiguts
docker_container_up == 0

L'arquitectura pull de Prometheus

A diferencia d'altres sistemes (que reben dades - "push"), Prometheus va a buscar-les ("pull"). Cada 15 segons (per defecte) Prometheus fa una peticio HTTP a un endpoint de cada servei.

[Prometheus] --GET /metrics--> [Node Exporter a RPi]
[Prometheus] --GET /metrics--> [cAdvisor dins Docker]
[Prometheus] --GET /metrics--> [HA, InfluxDB, etc.]

Avantatges: visibilitat, deteccio automatica de fallades, configuracio centralitzada. Desavantatges: serveis darrere NAT son complicats.

Els exporters

Un "exporter" es un petit programa que converteix l'estat intern d'un servei en metriques Prometheus. A la RPi del BernatLab en tindras uns quants:

  • node_exporter: CPU, memoria, disc, xarxa, temperatura. El mes important.
  • cadvisor: metricas dels contenidors Docker.
  • nginx_exporter: peticions, errors, latencia del proxy invers.
  • blackbox_exporter: probes HTTP, TCP, ICMP per serveis externs.

Instal·lacio a la RPi

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    restart: unless-stopped
    user: "0:0"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
      - ./prometheus/data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.retention.time=30d'
      - '--storage.tsdb.retention.size=2GB'
    ports:
      - "9090:9090"

  node-exporter:
    image: prom/node-exporter:latest
    container_name: node-exporter
    restart: unless-stopped
    pid: host
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /:/rootfs:ro
    command:
      - '--path.procfs=/host/proc'
      - '--path.sysfs=/host/sys'
      - '--path.rootfs=/rootfs'
    ports:
      - "9100:9100"

  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    container_name: cadvisor
    restart: unless-stopped
    privileged: true
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro
    ports:
      - "8080:8080"

Configuracio prometheus.yml

global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']
  - job_name: 'node'
    static_configs:
      - targets: ['node-exporter:9100']
  - job_name: 'cadvisor'
    static_configs:
      - targets: ['cadvisor:8080']
  - job_name: 'homeassistant'
    static_configs:
      - targets: ['homeassistant:8123']
    metrics_path: /api/prometheus

Despres accedeix a http://IP_RPI:9090 i comprova "Status" -> "Targets".

PromQL: el llenguatge de consultes

PromQL es sorprenentment poderos:

# Memoria lliure en GB
node_memory_MemAvailable_bytes / 1024 / 1024 / 1024

# Espai en disc lliure (%)
(node_filesystem_avail_bytes{mountpoint="/"} * 100) / node_filesystem_size_bytes{mountpoint="/"}

# Temperatura CPU (RPi)
node_thermal_zone_temp

# Taxa d'errors HTTP per minut
rate(http_requests_total{status=~"5.."}[5m])

Retencio i emmagatzematge

Per defecte Prometheus guarda 15 dies. A la RPi volem ser conservadors:

--storage.tsdb.retention.time=30d
--storage.tsdb.retention.size=2GB

Limitacions de la RPi

  • No posis masses targets: cada target son mes series i mes CPU.
  • scrape_interval mes alt: 30s en lloc de 15s alleugereix la carrega.
  • Cardinality baixa: no creis labels dinamics.
  • Retencio curta: evita que el disc s'ompli.

🛠️ Exercici pràctic (45-60 min)

Instal·lar Prometheus, node-exporter i cAdvisor a la teva RPi. Configurar els seus targets i fer les primeres consultes PromQL.

Pas 1: Crea l'estructura de carpetes (5 min)

cd ~/bernatlab
mkdir -p prometheus/data
ls -la prometheus/

Pas 2: Crea el fitxer prometheus.yml (10 min)

nano prometheus/prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']
  - job_name: 'node'
    static_configs:
      - targets: ['node-exporter:9100']
  - job_name: 'cadvisor'
    static_configs:
      - targets: ['cadvisor:8080']

Pas 3: Afegeix els serveis al docker-compose (10 min)

Edita el teu docker-compose.yml i afegeix els tres serveis nous (Prometheus, node-exporter, cAdvisor). Despres:

docker compose up -d prometheus node-exporter cadvisor
docker ps | grep -E "prometheus|exporter|cadvisor"

Pas 4: Verifica que tot funciona (10 min)

Accedeix a http://IP_RPI:9090/targets. Hauries de veure 3-4 targets, tots amb estat "UP" en verd. Si algun esta "DOWN", comprova els logs amb docker logs prometheus.

Pas 5: Fes les primeres consultes PromQL (15 min)

A http://IP_RPI:9090/graph, prova aquestes consultes:

# 1. CPU en us (per core, en %)
100 - (avg by(cpu)(rate(node_cpu_seconds_total{mode="idle"}[2m])) * 100)

# 2. Memoria disponible en GB
node_memory_MemAvailable_bytes / 1024 / 1024 / 1024

# 3. Espai lliure al disc principal (%)
(node_filesystem_avail_bytes{mountpoint="/"} * 100) / node_filesystem_size_bytes{mountpoint="/"}

# 4. Temperatura de la CPU (RPi)
node_thermal_zone_temp

# 5. Bytes rebuts a la xarxa
rate(node_network_receive_bytes_total{device!="lo"}[5m])

# 6. Memoria usada per contenidor
container_memory_usage_bytes{name=~".+"}

Pas 6: Mira les metricas raw (5 min)

# Metricas de la RPi
curl -s http://localhost:9100/metrics | grep node_thermal

# Metricas dels contenidors
curl -s http://localhost:8080/metrics | grep container_memory

# Comptador de series
curl -s http://localhost:9090/api/v1/status/tsdb | python3 -m json.tool

Validació

  • ☐ Prometheus, node-exporter i cAdvisor corren com a contenidors.
  • ☐ Els targets apareixen com a "UP" a la UI.
  • ☐ Has fet almenys 5 consultes PromQL amb resultats.
  • ☐ Pots veure la temperatura de la RPi.
  • ☐ Pots veure l'ús de memoria i CPU per contenidor.
  • ☐ Has explorat l'endpoint /metrics directament.

Resum ràpid

  1. Metrica = valor numeric + timestamp + labels opcionals.
  2. Model = pull (Prometheus truca al servei).
  3. Exporter = adaptador que exposa metricas en format Prometheus.
  4. Interval = 15 segons per defecte.
  5. Docker = cadvisor.
  6. Llenguatge = PromQL.
  7. Mida = --storage.tsdb.retention.size.
  8. Port = 9090.
