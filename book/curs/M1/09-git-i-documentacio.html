📖 Resum del capítol

La idea clau

Un homelab sense versionat és com cuinar sense recepta. Git et dona historial complet, capacitat de tornar enrere, i documentació viva. Versiones tot /home/bernat/homelab/ amb README, CHANGELOG i decisions.

Què és Git?

Sistema de control de versions distribuït. Permet guardar instantànies, veure què ha canviat, tornar enrere, treballar en branques, col·laborar. Tres estats: working directory, staging area, repository.

Per què versionar l'homelab?

  • Backup si la SD es trenca.
  • Comparar versions.
  • Experimentar en branques sense por.
  • Reproduir l'homelab en una altra màquina.
  • Ensenyar-ho a altres.

Estructura esperada

/home/bernat/homelab/
├── docker/docker-compose.yml
├── config/{homepage,portainer,uptime-kuma}/
├── scripts/
├── notes/{README,CHANGELOG,decisions,incidencies}.md

El flux diari

cd ~/homelab
git status          # què he canviat
git diff            # veure els canvis
git add .           # preparar
git commit -m "Missatge clar"
git push            # (opcional) pujar al remot

README.md: la porta del projecte

Cada bon projecte té un README amb: visió general, estructura, com començar, enllaços útils.

CHANGELOG.md: què ha canviat

Registre cronològic de canvis. Format: data, versió, llista d'afegits/canvis/correccions. Estàndard: Keep a Changelog.

notes/decisions.md (ADR)

Per a cada decisió arquitectònica: context, decisió, conseqüències. Exemple: per què Debian 13 i no Ubuntu. Per què Tailscale i no WireGuard.

notes/incidencies.md (postmortem)

Per a cada incident: símptomes, diagnòstic, solució, lliçó.

Allotjar el repo

Opcions: GitHub, GitLab, Codeberg, Gitea self-hosted, Forgejo. Recomanació al BernatLab: Gitea allotjat a la pròpia RPi.

Comandos útils

git log --oneline          # historial curt
git log --graph --all      # visual amb branques
git show <hash>            # veure un commit
git revert <hash>          # desfer un commit (commit invers)
git reset --hard <hash>    # PERILLOS: esborra canvis
git checkout -b nova        # crear i canviar a branca
git merge nova              # fusionar branca
git stash                   # guardar canvis temporalment

Bones pràctiques

  1. Commits petits i freqüents.
  2. Missatges clars (què i per què).
  3. Commit al final de cada sessió.
  4. Mai secrets al repo (.gitignore + .env).
  5. Branques per a experiments.
  6. Documenta el "per què".
  7. Backups regulars (repo + còpia fora de la RPi).

🛠️ Exercici pràctic (45-60 min)

Posar tot l'homelab sota control de versions amb Git i crear la documentació bàsica.

Pas 1: Inicialitza el repo (10 min)

Instal·la git, configura identitat, cd ~/homelab && git init.

Pas 2: .gitignore (5 min)

Cobreix secrets, logs, volums, fitxers temporals.

Pas 3: Estructura de notes (10 min)

Crea notes/ amb README, CHANGELOG, decisions, incidencies. Crea docs/ i scripts/.

Pas 4: Primer commit (5 min)

git add . && git commit -m "Estat inicial..."

Pas 5: Flux diari (15 min)

Crea scripts/info-rpi.sh, fes-lo executable, commita'l.

Pas 6: Canvi al compose (opcional, 10 min)

Afegeix un comentari, commita'l.

Pas 7: Documenta

Crea book/curs/M1/09-git-i-documentacio/diari.md amb sortida de git log --oneline.
