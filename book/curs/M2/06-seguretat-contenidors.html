📖 Resum del capítol

La idea clau

Un contenidor Docker no es un sandbox perfecte. Per defecte, un contenidor te mes privilegis dels que necessita: s'executa com a root, te capabilities del kernel Linux, pot muntar sistemes de fitxers, etc. Cal aplicar mesures de defensa en profunditat.

Defensa en profunditat

No n'hi ha prou amb una sola mesura. Cal combinar-ne varies:

  • Imatge minima i actualitzada
  • Usuari no-root
  • Capabilities minimes
  • Read-only filesystem
  • Xarxa aillada
  • Limitar recursos (CPU, RAM)
  • Sense privilegis
  • Seccomp / AppArmor

1. Usuari no-root

Per defecte, Docker executa els contenidors com a root (UID 0). Si un atacant explota el contenidor, sera root a dins.

# Definir-ho al run
docker run --user 1000:1000 meva-app

# O al Dockerfile
FROM python:3.12-slim
USER 1000

Truc important: abans de USER, copia els fitxers amb els permisos correctes:

FROM python:3.12-slim
WORKDIR /app
COPY --chown=1000:1000 . .
RUN pip install ...
USER 1000
CMD ["python", "app.py"]

2. Capabilities de Linux

Les capabilities son permisos especials que tradicionalment nomes te root. Docker ja en treu moltes per defecte, pero pots ser mes estricte:

# Treure totes
docker run --cap-drop=ALL meva-app

# Treure totes pero afegir nomes les que necessites
docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE meva-app

3. Read-only filesystem

El sistema de fitxers del contenidor es normalment escribible. Pots fer-lo nomes de lectura:

docker run --read-only meva-app

Aixi, el contenidor nomes pot escriure a volums muntats, tmpfs o la xarxa.

Pero moltes apps necessiten escriure a /tmp. Solucio: muntar tmpfs:

docker run --read-only --tmpfs /tmp:rw,noexec,nosuid meva-app

4. Mode privilegiat

Docker te un mode privileged que dona al contenidor quasi tots els privilegis de l'amfitrio:

docker run --privileged meva-app
# AIXO ES PERILLOS. NO HO FACIS MAI.

5. Seccomp (secure computing mode)

Seccomp es un mecanisme del kernel Linux que filtra les syscalls que un proces pot fer. Docker ja l'aplica per defecte amb un perfil segur.

docker run alpine grep Seccomp /proc/self/status
# Seccomp: 2 (mode filter)

6. No-new-privileges

Aquesta opcio evita que un procés dins el contenidor adquireixi nous privilegis (per exemple, amb setuid):

docker run --security-opt=no-new-privileges meva-app

7. Xarxa aillada

Usa xarxes custom per a que els serveis nomes estiguin exposats on toca.

8. Escaner de vulnerabilitats

Docker te una eina integrada per analitzar vulnerabilitats conegudes:

docker scan nginx:alpine

Alternativa mes potent: Trivy:

sudo apt install -y trivy
trivy image nginx:alpine
trivy image --severity HIGH,CRITICAL nginx:alpine

9. Limitar recursos

Un contenidor pot consumir tota la CPU/RAM de l'amfitrio si no el limites:

docker run --memory=512m --cpus=1.0 meva-app

10. Rootless Docker

L'opcio mes segura: executar el dimoni Docker sense root a l'amfitrio.

sudo apt install -y uidmap dbus-user-session
dockerd-rootless-setuptool.sh install

Resum: el "contenidor minim segur"

docker run -d \
  --name servei \
  --user 1000:1000 \
  --read-only \
  --cap-drop=ALL \
  --cap-add=NET_BIND_SERVICE \
  --security-opt=no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid \
  --memory=512m \
  --cpus=1.0 \
  --network xarxa-aillada \
  meva-app:1.0

🛠️ Exercici pràctic (30-45 min)

Practicar les principals mesures de seguretat per a contenidors Docker.

Pas 1: Configuracio per defecte (5 min)

docker run --rm alpine id
docker run --rm --security-opt no-new-privileges alpine \
  grep CapEff /proc/self/status
docker run --rm alpine sh -c "mount | head -5"

Pas 2: Insegur vs segur (15 min)

# INSEGUR
docker run -d --name nextcloud-insecure \
  -v ~/test-insecure:/var/www/html nextcloud

docker exec nextcloud-insecure id
docker exec nextcloud-insecure sh -c "echo 'pwned' > /root/pwned.txt"
docker stop nextcloud-insecure && docker rm nextcloud-insecure
rm -rf ~/test-insecure

# SEGUR
docker run -d --name nextcloud-secure \
  --user 33:33 --read-only --cap-drop=ALL \
  --security-opt=no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid \
  -v ~/test-secure:/var/www/html nextcloud

docker exec nextcloud-secure id
docker exec nextcloud-secure sh -c "echo 'test' > /etc/test.txt"
docker exec nextcloud-secure mount
docker exec nextcloud-secure ping -c 1 8.8.8.8
docker exec nextcloud-secure sh -c "su -"
docker stop nextcloud-secure && docker rm nextcloud-secure
rm -rf ~/test-secure

Pas 3: Escaner de vulnerabilitats (10 min)

docker scan --version
docker scan nginx:alpine
docker scan nginx:alpine --json | head -100

# Trivy (alternativa mes potent)
sudo apt install -y wget apt-transport-https gnupg
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/trivy.gpg] https://aquasecurity.github.io/trivy-repo/deb generic main" | sudo tee /etc/apt/sources.list.d/trivy.list
sudo apt update
sudo apt install -y trivy

trivy image nginx:alpine
trivy image --severity HIGH,CRITICAL nginx:alpine

Pas 4: Seccomp (5 min)

docker run --rm alpine sh -c "grep Seccomp /proc/self/status"
docker run --rm alpine sh -c "kmod list"
docker run --rm --security-opt seccomp=unconfined alpine sh -c "kmod list"

Pas 5: Auditar configuracio (5 min)

docker ps
for c in $(docker ps -q); do
  echo "=== $c ==="
  docker inspect $c --format 'User: {{.Config.User}}
ReadonlyRootfs: {{.HostConfig.ReadonlyRootfs}}
Privileged: {{.HostConfig.Privileged}}
CapAdd: {{.HostConfig.CapAdd}}
CapDrop: {{.HostConfig.CapDrop}}
SecurityOpt: {{.HostConfig.SecurityOpt}}'
done

Validació

  • ☐ Has vist la diferencia entre un contenidor root i un de no-root.
  • ☐ Has comprovat que un contenidor amb --read-only no pot escriure a /etc.
  • ☐ Has vist com les capabilities per defecte son limitades.
  • ☐ Has fet un escaneig de vulnerabilitats amb docker scan o trivy.
  • ☐ Has comprovat que seccomp esta activat per defecte.
  • ☐ Has auditat la teva configuracio actual.

Resum ràpid

  1. Root risk = explotacio amb acces massiu a l'amfitrio.
  2. Usuari no-root = --user 1000:1000.
  3. Rootless = Docker sense root a l'amfitrio.
  4. Capabilities = --cap-drop=ALL.
  5. Read-only = filesystem nomes de lectura.
  6. docker scan = analitza vulnerabilitats conegudes.
  7. --read-only = no permet modificar el filesystem del contenidor.
  8. Seccomp = filtra syscalls del kernel.
