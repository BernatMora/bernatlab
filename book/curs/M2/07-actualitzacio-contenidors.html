📖 Resum del capítol

La idea clau

Els serveis en contenidors s'han d'actualitzar periodicament: per seguretat (CVE nous), per noves funcionalitats, per compatibilitat. Hi ha dues maneres: manual o automàtica amb Watchtower.

Per que cal actualitzar

  • Seguretat: cada setmana es descobreixen noves vulnerabilitats.
  • Estabilitat: les versions noves solen corregir bugs.
  • Funcionalitats: cada versio aporta millores.
  • Compatibilitat: si tot evoluciona, el teu servei queda obsolet.

Risc: actualitzar pot trencar coses. Per això sempre es fa amb backup previ.

Com s'actualitza manualment

# Pas 1: backup (sempre abans!)

# Pas 2: parar el servei antic
docker compose down web

# Pas 3: baixar la nova imatge
docker compose pull web

# Pas 4: arrencar amb la nova versio
docker compose up -d web

# Pas 5: verificar
docker compose logs -f web

Watchtower: actualitzacio automatica

Watchtower es un contenidor que mira automaticament si hi ha noves versions de les imatges.

Instal·lacio

services:
  watchtower:
    image: containrrr/watchtower
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - WATCHTOWER_LABEL_ENABLE=true
      - WATCHTOWER_CLEANUP=true
      - WATCHTOWER_POLL_INTERVAL=86400

  nextcloud:
    image: nextcloud:stable
    labels:
      - "com.bernatlab.enable=true"  # nomes s'actualitza aquest

Configuracio important

# Nomes actualitzar contenidors amb label especific
WATCHTOWER_LABEL_ENABLE=true

# Esborrar imatges antigues
WATCHTOWER_CLEANUP=true

# Interval (cron format: min hora dia mes dia_setmana)
--schedule "0 0 4 * * *"  # cada dia a les 4 AM
WATCHTOWER_POLL_INTERVAL=86400

# Notificacions
WATCHTOWER_NOTIFICATIONS=shoutrrr
WATCHTOWER_NOTIFICATION_URL=shoutrrr://discord://token@channel

Bones practiques

  1. Label nomes el que vulguis actualitzar.
  2. Backup abans d'actualitzar: Watchtower no fa backups.
  3. Notifications: configura Watchtower per a que t'avisi.
  4. Interval raonable: un cop al dia es el minim.
  5. Monitoritza els logs: revisa els logs de Watchtower regularment.

Rolling updates i blue-green

Rolling update

Substituir instancies una a una:

Inici:    [v1] [v1] [v1]   <- 3 instancies
Pas 1:    [v2] [v1] [v1]   <- substituim la 1
Pas 2:    [v2] [v2] [v1]
Final:    [v2] [v2] [v2]   <- tot actualitzat

Amb Compose normal, manualment:

docker compose up -d --no-deps --scale web=2 web
docker compose up -d --no-deps --scale web=1 web

Blue-green deployment

Tenir dues versions corrent en paral·lel i canviar el tràfic nomes quan la nova funciona.

Healthchecks: el cor de l'autohealing

services:
  web:
    image: nginx
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
    restart: unless-stopped

Limitacions de Watchtower

  • No fa backups
  • No sempre enten l'API (scripts d'upgrade)
  • Pot trencar volums si canvia el format
  • No es bo per a bases de dades sense un upgrade plan

Recomanacio al BernatLab: Watchtower nomes per a serveis "menors". Manual per a serveis critics. Sempre amb backup previ.

🛠️ Exercici pràctic (30-45 min)

Practicar Watchtower, rolling updates i blue-green deployment.

Pas 1: Prepara el projecte (5 min)

mkdir -p ~/actualitzacio-test
cd ~/actualitzacio-test

Crea un docker-compose.yml:

version: "3.8"
services:
  web:
    image: nginx:1.25-alpine
    ports:
      - "8080:80"
    labels:
      - "com.bernatlab.enable=true"

  watchtower:
    image: containrrr/watchtower
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - WATCHTOWER_LABEL_ENABLE=true
      - WATCHTOWER_CLEANUP=true
      - WATCHTOWER_POLL_INTERVAL=60
    command: --label-enable --cleanup

Pas 2: Arrenca i verifica (5 min)

docker compose up -d
docker compose ps
curl -s http://localhost:8080 | head -5
docker exec actualitzacio-test-web-1 nginx -v

Pas 3: Watchtower monitoritza (10 min)

docker compose logs watchtower
docker exec actualitzacio-test-watchtower-1 watchtower --debug

Pas 4: Forca una actualitzacio (10 min)

docker compose down
sed -i 's|nginx:1.25-alpine|nginx:1.27-alpine|g' docker-compose.yml
docker compose up -d
docker exec actualitzacio-test-web-1 nginx -v

Pas 5: Blue-green manual (10 min)

mkdir -p ~/actualitzacio-test/green
cd ~/actualitzacio-test/green

cat > docker-compose.yml <

Pas 6: Notificacions (5 min)

cd ~/actualitzacio-test
docker compose down

cat > docker-compose.yml <

Pas 7: Neteja

cd ~/actualitzacio-test
docker compose down
rm -rf ~/actualitzacio-test
docker system prune -a --volumes

Resum ràpid

  1. Watchtower = actualitza automatic.
  2. Update vs upgrade = update es el proces, upgrade es canviar versio major.
  3. Blue-green = dues versions corrent.
  4. Rolling update = instancies una a una.
  5. Labels = controlar quins s'actualitzen.
  6. Interval = 86400 (1 cop al dia).
  7. Healthcheck = comanda per saber si funciona.
  8. Zero-downtime = actualitzar sense tall del servei.
