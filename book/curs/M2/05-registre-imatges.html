📖 Resum del capítol

La idea clau

Un registre d'imatges es un servidor que emmagatzema imatges Docker i les distribueix. Docker Hub es el mes conegut, pero per a un homelab es molt recomanable tenir un registre privat per seguretat, velocitat i control.

Que es un registre

Un registre es simplement una API HTTP que segueix l'estandard "Docker Registry HTTP API V2". Permet:

  • Pujar imatges (docker push)
  • Baixar imatges (docker pull)
  • Llistar imatges i tags
  • Esborrar imatges
  • Gestionar permisos (autenticacio)

Docker Hub

El registre public per defecte. Tots hi tenim un compte gratuït.

docker login
docker tag meva-app:1.0 bernatmora/meva-app:1.0
docker push bernatmora/meva-app:1.0
docker pull bernatmora/meva-app:1.0

Limitacions del pla gratuit: 1 registre privat, 200 pulls per 6 hores, imatges publiques il·limitades.

Registre privat: opcions

1. Docker Registry oficial (la imatge registry)

Es la mes simple. Es un contenidor que només fa de registre.

docker run -d -p 5000:5000 --restart=always --name registry \
  -v /home/pi/registry-data:/var/lib/registry \
  registry:2

Avantatges: simple, lleuger, perfecte per a homelab. Desavantatges: sense UI, sense autenticacio per defecte.

2. Harbor

Solucio completa de registre. Te UI web, autenticacio LDAP/AD, escaneig de vulnerabilitats, replicacio.

Avantatges: UI, seguretat, integracio LDAP, escaneig de vulnerabilitats. Desavantatges: mes pesat, mes complexe.

3. GitHub Container Registry (ghcr.io)

Si ja tens codi a GitHub, pots usar el seu registre gratuit.

docker login ghcr.io -u bernatmora
docker tag meva-app:1.0 ghcr.io/bernatmora/meva-app:1.0
docker push ghcr.io/bernatmora/meva-app:1.0

Autenticacio

Sense autenticacio, el registre es obert a tothom. El registry:2 oficial porta un sistema basic:

# Crear usuari amb htpasswd
docker run --rm --entrypoint htpasswd httpd:2 -Bbn bernat supersecret > auth/htpasswd

# Arrencar amb autenticacio
docker run -d -p 5000:5000 --restart=always --name registry \
  -v /home/pi/registry-data:/var/lib/registry \
  -v $(pwd)/auth:/auth \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2

# Login
docker login raspberry.local:5000

TLS: HTTPS es obligatori

Docker nomes permet pujar/baixar imatges a registres HTTPS. Si tens un registre a raspberry.local:5000 nomes amb HTTP, has de dir-li a Docker que el confia:

{
  "insecure-registries": ["raspberry.local:5000"]
}

Pero la recomanacio es posar HTTPS. Usa Caddy o Traefik com a reverse proxy.

Mirror de Docker Hub

Pots configurar un mirror local. El registre oficial pot actuar com a cache:

version: 0.1
proxy:
  remoteurl: https://registry-1.docker.io

🛠️ Exercici pràctic (30-45 min)

Muntar un registre Docker privat a la teva RPi, configurar autenticacio, pujar-hi una imatge.

Pas 1: Arrenca el registre basic (5 min)

mkdir -p ~/registry-data

docker run -d -p 5000:5000 --restart=always --name registry \
  -v ~/registry-data:/var/lib/registry \
  registry:2

curl http://localhost:5000/v2/
curl http://localhost:5000/v2/_catalog

Pas 2: Configura insecure-registries (5 min)

hostname -I
sudo nano /etc/docker/daemon.json
{
  "insecure-registries": ["192.168.1.100:5000"]
}
sudo systemctl restart docker
docker start registry

Pas 3: Puja una imatge (10 min)

docker pull alpine
docker tag alpine:latest 192.168.1.100:5000/meu-alpine:1.0
docker push 192.168.1.100:5000/meu-alpine:1.0
curl http://localhost:5000/v2/_catalog
curl http://localhost:5000/v2/meu-alpine/tags/list

Pas 4: Baixa la imatge (5 min)

docker rmi 192.168.1.100:5000/meu-alpine:1.0
docker pull 192.168.1.100:5000/meu-alpine:1.0
docker run --rm 192.168.1.100:5000/meu-alpine:1.0 echo "Hola!"

Pas 5: Autenticacio (10 min)

mkdir -p ~/registry-auth
docker run --rm --entrypoint htpasswd httpd:2 -Bbn bernat supersecret > ~/registry-auth/htpasswd
cat ~/registry-auth/htpasswd

docker stop registry
docker rm registry

docker run -d -p 5000:5000 --restart=always --name registry \
  -v ~/registry-data:/var/lib/registry \
  -v ~/registry-auth:/auth \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2

curl http://localhost:5000/v2/_catalog
curl -u bernat:supersecret http://localhost:5000/v2/_catalog

Pas 6: Login (5 min)

docker logout
docker login 192.168.1.100:5000
cat ~/.docker/config.json
docker push 192.168.1.100:5000/meu-alpine:1.0

Pas 7: Inspecciona

curl -u bernat:supersecret http://localhost:5000/v2/_catalog
curl -u bernat:supersecret http://localhost:5000/v2/meu-alpine/tags/list
docker logs registry --tail 50

Validació

  • ☐ Has arrencat un registre Docker privat al port 5000.
  • ☐ Has configurat insecure-registries per fer-hi accessible.
  • ☐ Has pujat una imatge amb docker push i l'has tornat a baixar.
  • ☐ Has afegit autenticacio htpasswd i has fet login.
  • ☐ Has vist la llista d'imatges al registre amb la API REST.

Resum ràpid

  1. Registre public per defecte = Docker Hub.
  2. Imatge oficial = registry:2.
  3. Privat = seguretat, velocitat, control.
  4. Pujar = docker push.
  5. HTTP = rebutjat (excepte insecure-registries).
  6. Complet = Harbor.
  7. Dades = /var/lib/registry/ dins el contenidor.
  8. Config = /etc/docker/daemon.json.
