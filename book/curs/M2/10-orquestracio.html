📖 Resum del capítol

La idea clau

Quan tens un sol servidor (la RPi del BernatLab), no necessites orquestracio. Docker Compose en te prou. Pero quan tens varis servidors o vols alta disponibilitat, cal una eina d'orquestracio. Les dues mes populars son Docker Swarm i Kubernetes.

Que es l'orquestracio

L'orquestracio es la gestio automatitzada de contenidors en multiples maquines. Un orquestrador s'encarrega de:

  • Desplegar contenidors en el node mes adequat.
  • Escalar (afegir mes instancies si hi ha mes carrega).
  • Auto-healing (reiniciar contenidors que fallen).
  • Rolling updates (actualitzar sense temps d'inactivitat).
  • Service discovery (trobar on son els serveis).
  • Load balancing (repartir el tràfic entre instancies).
  • Networking entre nodes (xarxa que travessa maquines).

Quan necessites orquestracio

No ho necessitis si:

  • Tens un sol node (una sola RPi, un sol servidor).
  • Tens pocs serveis (5-10 contenidors).
  • Tens baix tràfic (<1000 peticions/segon).
  • No et cal alta disponibilitat.

Si ho necessites si:

  • Tens multiples servidors.
  • Necessites alta disponibilitat.
  • Tens molts serveis (20-50 contenidors o mes).
  • Necessites escalar automaticament.

Docker Swarm: la opcio "facil"

Docker Swarm es el mode Swarm de Docker. Ja esta integrat a Docker.

Caracteristiques

  • Integrat a Docker: no cal instal·lar res.
  • Declaratiu amb stacks: docker stack deploy -c compose.yml stack-name.
  • Rolling updates nadius.
  • Networking overlay: xarxa que travessa nodes.
  • Secrets i configs: integrats.
  • Simplicitat: el pots aprendre en una tarda.

Cas d'us: cluster de RPi

[Manager]   <- gestiona el cluster
   |
   +-- [Worker 1]  <- executa els teus serveis
   |
   +-- [Worker 2]  <- executa els teus serveis

Kubernetes: la opcio "professional"

Kubernetes (K8s) es l'estandard de la industria. Creat per Google, ara open source.

Caracteristiques

  • Estandard de la industria.
  • Molt potent: rolling updates, auto-scaling, auto-healing.
  • Ecosistema gran.
  • Multi-cloud: AWS, GCP, Azure o on-prem.
  • Complex: corba d'aprenentatge pronunciada.
  • Recursos intensius: minim 3-5 servidors, 8 GB RAM cada un.

Alternatives a Kubernetes pur

  • K3s: Kubernetes lleuger. ~200 MB. Perfecte per a RPi.
  • K3d: K3s en contenidors Docker.
  • microK8s: de Canonical.
  • Minikube: per a desenvolupament local.

Comparativa

  • Dificultat: Swarm baixa, K8s alta.
  • Recursos minims: Swarm 1-2 nodes 1 GB, K8s 3-5 nodes 4-8 GB.
  • Ecosistema: Swarm petit, K8s gegant.
  • Cloud providers: Swarm limitats, K8s tots.
  • Adequat per homelab: Swarm si (petit), K8s amb K3s.

Exemple Swarm

# Inicialitzar
docker swarm init

# Desplegar un stack
docker stack deploy -c docker-compose.yml bernatlab

# Veure serveis
docker service ls

# Escalar
docker service scale bernatlab_web=5

# Rolling update
docker service update --image nginx:1.27 bernatlab_web

Exemple K3s

# Servidor
curl -sfL https://get.k3s.io | sh -

# Worker
curl -sfL https://get.k3s.io | K3S_URL=https://<server>:6443 K3S_TOKEN=<token> sh -

# kubectl ja esta disponible
kubectl get nodes
kubectl apply -f deployment.yaml

El cami al BernatLab

Si estas content amb el teu homelab actual (una sola RPi), no et cal orquestracio. Si vols mes:

  1. Monta un cluster Swarm amb 3 RPi. Es la opcio mes facil.
  2. Prova K3s. Et dona Kubernetes real amb pocs recursos.
  3. Migra serveis individuals al cluster, mantenint Compose per als serveis simples.
  4. Apren kubectl si vols fer el salt a K8s.

🛠️ Exercici pràctic (30-45 min)

Practicar amb un mini cluster Docker Swarm i investigar K3s.

Pas 1: Swarm d'un sol node (5 min)

docker swarm init
docker node ls
docker swarm join-token manager
docker swarm join-token worker

Pas 2: Desplega amb Swarm (10 min)

mkdir -p ~/swarm-test
cd ~/swarm-test

Crea stack.yml:

version: "3.8"
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 10s
      restart_policy:
        condition: on-failure
    networks:
      - webnet

networks:
  webnet:
    driver: overlay
docker stack deploy -c stack.yml swarm-test
docker service ls
docker service ps swarm-test_web
curl http://localhost:8080
docker service inspect swarm-test_web

Pas 3: Escalar (5 min)

docker service scale swarm-test_web=5
docker service ps swarm-test_web
docker service scale swarm-test_web=2
docker service ps swarm-test_web

Pas 4: Rolling update (10 min)

docker service update --image nginx:1.27-alpine swarm-test_web
docker service ps swarm-test_web
docker exec $(docker ps -q -f "name=swarm-test_web") nginx -v

Pas 5: Auto-healing (5 min)

docker service ps swarm-test_web
CONTAINER=$(docker ps -q -f "name=swarm-test_web" | head -1)
docker rm -f $CONTAINER
sleep 5
docker service ps swarm-test_web

Pas 6: Neteja (5 min)

docker stack rm swarm-test
docker swarm leave --force
docker node ls

Pas 7: Investiga K3s (opcional) (10 min)

curl -sfL https://get.k3s.io | sh -
sleep 30
sudo kubectl get nodes
sudo kubectl create deployment nginx --image=nginx
sudo kubectl expose deployment nginx --port=80 --type=LoadBalancer
sudo kubectl get services
curl http://localhost
sudo kubectl delete service nginx
sudo kubectl delete deployment nginx
/usr/local/bin/k3s-uninstall.sh

Pas 8: Reflexio (5 min)

docker ps --format "{{.Names}}"
docker stats --no-stream
hostname

Validació

  • ☐ Has inicialitzat i sortit d'un Swarm d'un sol node.
  • ☐ Has desplegat un stack amb multiples replicas.
  • ☐ Has vist com Swarm fa rolling updates i auto-healing.
  • ☐ Has investigat K3s o has decidit que no el necessites ara.
  • ☐ Has reflexionat sobre quan et cal orquestracio al BernatLab.

Resum ràpid

  1. Orquestrador = gestio automatica de contenidors en multiples maquines.
  2. Integrat a Docker = Swarm.
  3. Estandard = Kubernetes.
  4. K8s lleuger per RPi = K3s.
  5. Sense orquestrador = 1 node, pocs serveis.
  6. Alta disponibilitat = un node pot caure sense parar el servei.
  7. K8s inconvenient = mes complex i mes recursos.
  8. Swarm minim = 3 RPi.
