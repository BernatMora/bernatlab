📖 Resum del capitol

La idea clau

Un prompt es la pregunta o instruccio que dones a un LLM. La diferencia entre un bon i un mal prompt pot ser la diferencia entre una resposta inutil i una meravellosa. Prompt engineering es l'art d'escriure prompts que extreuen el millor del model. I no es magia: son patrons que es poden aprendre.

Per que importa al BernatLab?

Si volem que el nostre LLM local ens ajudi amb tasques reals (resumir logs, generar scripts, respondre sobre l'Hort Osona), hem de saber com parlar-li. Un prompt mal escrit donara respostes vagues o equivocades, i acabarem pensant que el model es dolent quan en realitat el problema es nostre.

Principi 1: Sigues especific

Mal prompt: Explica els servidors.

Bon prompt: Explica quines son les 3 diferencies principals entre un servidor HTTP com Nginx i un servidor d aplicacions com Gunicorn, en menys de 100 paraules.

El model no pot endevinar quina informacio vols, ni quin nivell de detall, ni en quin format. Si no li dius, et donara la resposta mes generica possible (que sol ser la menys util).

Principi 2: Dona context (rol i situacio)

Mal prompt: Com puc millorar la seguretat?

Bon prompt: Soc un administrador de sistemes amb una Raspberry Pi 4 que te un servidor SSH obert a Internet. Dona'm 5 consells concrets per millorar la seguretat, ordenats per prioritat.

Especificar qui ets, quina es la teva situacio i quina informacio necessites ajuda el model a donar-te una resposta a la teva mida.

Principi 3: Dona exemples (few-shot)

Si el model no enten el format que vols, mostra-l'hi amb exemples. Es la tecnica few-shot:

Classifica el sentiment de cada critica. Respon nomes amb "positiu" o "negatiu".

Critica: "Molt bon llibre, l he gaudit"
Sentiment: positiu

Critica: "Pessima compra, no ho recomano"
Sentiment: negatiu

Critica: "El llibre es avorrit i mal escrit"
Sentiment:

Principi 4: Indica el format de sortida

Llista els 5 avantatges principals de Docker. Per cada avantatge:
- Titol en negreta
- Explicacio en 1-2 frases
- Comanda d'exemple si escau

Utilitza aquest format Markdown:

## [Titol]
[Explicacio]
`[comanda]`

Principi 5: Demana pas a pas (chain of thought)

Per a tasques complexes, fer que el model "pensi pas a pas" millora molt la qualitat:

Quants dies te un periode de 5 anys si hi ha 3 anys de traspas?
Pensa pas a pas:
1. Quants dies te un any normal?
2. Quants dies te un any de traspas?
3. Calcula els dies totals.

Principi 6: Dona restriccions negatives

Explica què es Kubernetes. No donis exemples de codi. No comparis amb altres eines. Limita't a una definicio clara en 3-4 frases.

Principi 7: Usa delimitadors

[INSTRUCCIONS]
Ets un assistent que classifica correus.

[CORREU]
From: jordi@example.com
...

[CATEGORIES]
- tecnic
- comercial

[TASCA]
Respon nomes amb el nom de la categoria.

Tecnica bonus: System prompt

{
  "messages": [
    {"role": "system", "content": "Ets un expert en Docker. Respon sempre en catala. Dona exemples de comandes quan sigui relevant."},
    {"role": "user", "content": "Com puc veure els logs d un contenidor?"}
  ]
}

El system prompt es mante a totes les converses. Es ideal per a instruccions permanents.

Com mesurar la qualitat d'un prompt

  • Repetibilitat: 5 preguntes iguals, respostes similars?
  • Especificitat: conte la informacio que necessitaves?
  • Format: esta en el format esperat?
  • Al·lucinacions: s'ha inventat alguna dada?
  • Longitud: es adequat?

Errors comuns

  • Preguntes massa obertes: "Explica la historia".
  • Suposar context: "Fes la cosa aquella".
  • No validar: creure's la primera resposta.
  • Ignorar el catala: no especificar idioma.
  • Prompts massa llargs: mes llargs que la finestra de context.

Una plantilla que funciona

[ROL]
Ets un [professio] amb [X] anys d'experiencia en [camp].

[TASCA]
[Descripcio clara del que vols]

[RESTRICCIONS]
- Respon en [idioma]
- Limita la resposta a [N] paraules
- Usa [format] especific
- No [accio no desitjada]

[EXEMPLES] (opcional)
Input: [exemple]
Output: [exemple esperat]

[INPUT]
[Les teves dades concretes]

🛠️ Exercici practic (30-45 min)

Experimentar amb diferents tecniques de prompt engineering aplicades a analitzar logs del sistema.

Pas 1: Crea un directori amb dades de prova (5 min)

mkdir -p ~/bernatlab-exercicis/M4/04-prompts/dades
cd ~/bernatlab-exercicis/M4/04-prompts/dades

cat > logs.txt << 'EOF'
Mar 15 03:42:17 rpi sshd[1234]: Failed password for root from 185.143.223.47 port 44231 ssh2
Mar 15 03:42:18 rpi sshd[1234]: Failed password for root from 185.143.223.47 port 44231 ssh2
... (mes linies) ...
EOF

cat logs.txt

Pas 2: Prompt MAL dissenyat (5 min)

curl -s http://localhost:11434/api/generate -d '{
  "model": "llama3.2:3b",
  "prompt": "Que hi ha en aquest log?",
  "stream": false
}' | jq -r '.response'

Pas 3: Prompt amb rol i contexte (10 min)

Usa /api/chat amb system prompt "Ets un expert en seguretat informatica. Analitza logs de Linux en angles i respon sempre en catala." i user prompt ben estructurat amb el log.

Pas 4: Few-shot amb exemples (10 min)

Prompt amb 2 exemples de classificacio de logs abans de la pregunta real.

Pas 5: Chain-of-thought (10 min)

Prompt amb 5 passos numerats que el model ha de seguir per analitzar el log.

Pas 6: Documenta la comparacio (10 min)

Crea book/curs/M4/04-prompt-engineering/comparacio.md amb una taula comparativa de les 4 tecniques provades i les conclusions.

Validacio

  • ☐ Has provat el prompt MAL dissenyat.
  • ☐ Has provat el prompt amb rol i contexte.
  • ☐ Has provat el prompt amb few-shot.
  • ☐ Has provat el prompt amb chain-of-thought.
  • ☐ Has documentat la comparacio.

✅ Respostes

Les respostes completes amb explicacions estan al fitxer respostes.md del repositori.

Resum rapid

  1. Prompt = la pregunta o instruccio al LLM.
  2. Few-shot = amb exemples del format esperat.
  3. Bon prompt = amb rol, contexte i format especific.
  4. Chain-of-thought = pas a pas, deixant raonar el model.
  5. System prompt = instruccions permanents del rol.
  6. Delimitadors = ajuden a distingir parts del prompt.
  7. Error comu = preguntes massa obertes.
  8. Format JSON = especificar que sigui nomes JSON valid.
