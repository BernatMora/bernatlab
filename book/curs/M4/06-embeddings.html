📖 Resum del capitol

La idea clau

Un embedding es una llista de numeros (un vector) que representa el significat d'un text. Dues frases amb significat semblant tindran vectors propers; dues frases amb significat diferent tindran vectors allunyats. Es la manera que tenen les maquines de "mesurar" la semblança entre textos, i es el component magic que fa funcionar RAG.

Que es exactament un embedding?

Un embedding es un vector de N dimensions (normalment 384, 768, 1024 o 1536) on cada dimensio representa algun aspecte del significat del text. Per exemple:

  • "El gat dorm al sofà" -> [0.12, -0.34, 0.78, ..., 0.45] (768 numeros)
  • "El moix esta estirat al moble" -> [0.14, -0.32, 0.76, ..., 0.43] (molt semblant!)

Aquests dos vectors son propers perque les frases volen dir el mateix, encara que les paraules siguin diferents.

Com es calculen?

Un embedding es calcula passant el text per una xarxa neuronal entrenada especificament per aixo:

  • Word2Vec / GloVe (antics): un embedding per paraula.
  • Sentence Transformers: embeddings per frase o paragraf. Estanard actual.
  • OpenAI text-embedding-3-small: 1536 dimensions, comercial.
  • BGE / E5 / nomic-embed: models especialitzats, oberts.
  • Ollama embeddings: integrats a Ollama.

Semblança cosinus

import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

El resultat es un numero entre -1 i 1:

  • 1.0: significat identic.
  • 0.7-0.9: molt semblant.
  • 0.4-0.7: relacionat.
  • 0.0-0.4: poc relacionat.
  • 0.0 o menys: no relacionat o oposat.

Com fer una cerca eficient amb embeddings

  1. Indexacio: per cada text, calcula el seu embedding i guarda'l.
  2. Query: donada una pregunta, calcula el seu embedding i busca els K mes propers.
  3. Filtratge: un cop tens els top-K, pots filtrar per data, autor, categoria, o re-ranking.

Com triar el model d'embeddings

  • Simplicitat: usa el que ja tens amb Ollama (nomic-embed-text).
  • Maxima qualitat: mxbai-embed-large o un de HuggingFace especialitzat.
  • Pocs textos (menys de 1000): la diferencia es poca.
  • Milers de textos: inverteix en un bon model.
  • Text tecnic: busca un model entrenat en dades tecniques.
  • Multilingüe: bge-m3 o nomic-embed-text.

Bones practiques

  • Normalitza els vectors abans de calcular semblances.
  • Talla textos massa llargs (max ~512 tokens per text).
  • Neteja el text (treu headers, peu de pagina).
  • Guarda metadades junt amb l'embedding.
  • Re-indexa periodicament.
  • Fes proves amb validacio.

Limitacions dels embeddings

  • No entenen el context complet.
  • Multilinguisme limitat (millor en angles).
  • Cost de calcul: 1000 texts poden trigar minuts sense GPU.
  • Ceguesa a la semantica fina (ironia, sarcasme).
  • No son magics.

🛠️ Exercici practic (30-45 min)

Practicar amb embeddings de veritat: generar-ne, comparar semblances, i entendre quan funcionen be i quan fallen.

Pas 1: Instal·la un model d'embeddings (3 min)

ollama pull nomic-embed-text
ollama list

Pas 2: Genera embeddings des de la terminal (5 min)

curl -s http://localhost:11434/api/embeddings -d '{
  "model": "nomic-embed-text",
  "prompt": "El gat dorm al sofa"
}' | python3 -c "import json,sys; d=json.load(sys.stdin); print('Dimensions:', len(d['embedding']))"

Pas 3: Compara semblances manualment (10 min)

Crea proves.py amb 6 parelles de textos amb diferent grau de semblança. Calcula la semblança cosinus de cada parell. Els resultats coincideixen amb la teva intuicio?

Pas 4: Cerca per significat vs paraules (10 min)

Crea cerca_comparada.py amb una base de 10 documents de l'Hort Osona. Fes 4 consultes i observa com els embeddings troben relacions que la cerca per paraules no trobaria.

Pas 5: Visualitza amb un heatmap (10 min)

Crea visualitza.py que imprimeix una matriu de semblances entre 8 textos curts. Observa el patro.

Pas 6: Documenta conclusions (5 min)

Crea book/curs/M4/06-embeddings/observacions.md amb les teves conclusions.
