📖 Resum del capitol

La idea clau

No tots els models valen per a tot. Un model de 70B parametres donara respostes impressionants pero necessita un servidor de 50.000 euros. Un de 1B es rapid pero sembla tonto. La gracia esta en trobar el punt just: el model mes petit que et dona la qualitat que necessites pel teu hardware.

Que vol dir "X B parametres"?

Els parametres son els numeros que el model ha après durant l'entrenament. Mes parametres = mes capacitat (fins a un punt). Mes parametres = mes RAM i mes lent.

  • 1B parametres: ~2 GB en RAM (Q4). Molt basic, pero valid.
  • 3B: ~2.5 GB. Serveix per a feines simples.
  • 7B: ~4-5 GB. Bona qualitat, sweet spot per a molts casos.
  • 13B: ~8 GB. Notable.
  • 30B: ~18 GB. Excel·lent pero ja cal maquina potent.
  • 70B: ~40 GB. Nomes amb GPU.

La regla: cada 2x parametres necessita ~2x mes RAM.

Que es la quantitzacio?

Els models s'entrenen en float32 (32 bits per numero). Per executar-los en hardware modest, es poden comprimir a:

  • Q8 (8 bits): ocupacio ~25% del original, perdua minima.
  • Q4 (4 bits): ocupacio ~12.5%, perdua moderada. La mes comuna.
  • Q2 (2 bits): ocupacio ~6%, perdua important.

Exemple: un model de 7B en float32 ocupa 28 GB. En Q4, nomes 4 GB.

Quin model triar per a la RPi 4 (4 GB)?

  • llama3.2:1b: 1.3 GB, ~1.2 GB RAM, 30+ t/s, basica.
  • llama3.2:3b: 2.0 GB, ~2.5 GB RAM, 10-15 t/s, bona.
  • phi3:mini (3.8B): 2.3 GB, ~3 GB RAM, 8-12 t/s, molt bona.
  • gemma2:2b: 1.6 GB, ~1.8 GB RAM, 20+ t/s, bona.
  • mistral:7b: 4.1 GB, ~5 GB RAM, no a RPi 4, excel·lent.

Recomanacio per a la RPi 4: per defecte llama3.2:3b (bon equilibri). Per velocitat llama3.2:1b. Per qualitat i paciencia phi3:mini.

Models especialitzats

  • CodeLlama / CodeGemma: optimitzats per a codi.
  • Mistral / Llama: generals, bons per a xat i resums.
  • Phi-3: optimitzat per a raonament logic.
  • Llama 3.2 Vision: processa imatges. Requereix mes memoria.
  • Nomic-Embed / MXBAI-Embed: nomes per a embeddings.

Com avaluar la qualitat d'un model

Benchmarks estandard:

  • MMLU: coneixements generals.
  • HumanEval: generar codi Python correcte.
  • GSM8K: problemes matematics.
  • HellaSwag: sentit comu.

En la practica: proba el model amb les teves preguntes tipiques.

Com canviar de model a Ollama

ollama list

curl http://localhost:11434/api/generate -d '{
  "model": "phi3:mini",
  "prompt": "...",
  "stream": false
}'

Estrategies per a hardware limitat

  • Usa models mes petits (1B-3B).
  • Limita la longitud amb num_predict: {"num_predict": 200}.
  • Limita la finestra amb num_ctx: {"num_ctx": 2048}.
  • Usa swap al disc.
  • Configura OLLAMA_MAX_LOADED_MODELS=1.

Quant triga un model a carregar?

  • 1B Q4: 1-3 segons (SSD).
  • 3B Q4: 3-8 segons.
  • 7B Q4: 8-20 segons.
  • 13B Q4: 15-40 segons.

Un cop carregat, 5-30 tokens/s en RPi 4.

OLLAMA_KEEP_ALIVE: "5m" (per defecte), "1h", "-1" (sempre), "0" (mai).

🛠️ Exercici practic (30-45 min)

Comparar 3-4 models diferents amb les mateixes preguntes per entendre quin s'adapta millor a les teves necessitats.

Pas 1: Descarrega 3 models per comparar (15-20 min)

ollama pull llama3.2:1b
ollama pull llama3.2:3b
ollama pull gemma2:2b
ollama list

Opcional: ollama pull phi3:mini.

Pas 2: Crea un script de comparacio (10 min)

Crea ~/bernatlab-exercicis/M4/03-models/comparem.sh:

#!/bin/bash
MODELS=("llama3.2:1b" "llama3.2:3b" "gemma2:2b" "phi3:mini")
PREGUNTA="Explica en 3 frases per que es important fer copies de seguretat dels logs dun servidor."

for model in "${MODELS[@]}"; do
  echo "=========================================="
  echo "Model: $model"
  echo "=========================================="
  start=$(date +%s.%N)
  response=$(curl -s http://localhost:11434/api/generate -d "{
    \"model\": \"$model\",
    \"prompt\": \"$PREGUNTA\",
    \"stream\": false
  }")
  end=$(date +%s.%N)

  echo "$response" | jq -r '.response'
  echo ""
  echo "Temps total: $(echo "$end - $start" | bc) segons"
  echo "Tokens generats: $(echo "$response" | jq '.eval_count')"
  echo ""
done
chmod +x comparem.sh
sudo apt install jq bc -y
./comparem.sh

Resum rapid

  1. "B" parametres = Bilions.
  2. 7B Q4 = 4-5 GB RAM.
  3. Q4 = 4 bits per parametre.
  4. RPi 4 = llama3.2:3b.
  5. Bona velocitat = 10-20 t/s.
  6. num_predict = limita tokens generats.
  7. KEEP_ALIVE=-1 = sempre carregat.
  8. Codi = HumanEval.
