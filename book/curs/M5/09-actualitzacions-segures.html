📖 Resum del capítol

La idea clau

La majoria d'atacs exitosos aprofiten vulnerabilitats conegudes que tenen pegat disponible pero que no s'ha aplicat. Mantenir el sistema actualitzat es una de les mesures mes efectives, i alhora mes obvies. Al BernatLab volem un sistema que s'actualitzi sol, de forma controlada, sense trencar res, i que ens avisi quan hi ha pegats de seguretat pendents. Inclou tant el sistema operatiu (apt) com les imatges Docker (dependabot o Watchtower).

Per que les actualitzacions son critiques

Els CVE (Common Vulnerabilities and Exposures) son el registre public de vulnerabilitats conegudes. Quan es descobreix una, normalment tambe es publica una correcio (pegat). Si no apliques el pegat, la teva maquina queda exposada a un atac que ja es public.

Hi ha una regla empirica: el 80% dels atacs exitosos aprofiten pegats que estaven disponibles mesos abans. A mes, les actualitzacions:

  • Corregeixen errors de funcionalitat.
  • Afegeixen funcionalitats noves.
  • Milloren la performance.
  • S'adapten a canvis de l'entorn.

Tipus d'actualitzacions al BernatLab

Quatre tipus principals:

  • Sistema operatiu (Debian/Raspberry Pi OS): paquets apt.
  • Imatges Docker: imatges base, imatges dels serveis.
  • Aplicacions no Docker: scripts, eines instal·lades manualment.
  • Firmware: del router, de la BIOS, del microcontrolador de la RPi.

apt: actualitzar el sistema

apt es el gestor de paquets de Debian/Ubuntu. Comandes essentials:

# Veure quines actualitzacions hi ha
sudo apt update

# Llistar les actualitzacions disponibles
apt list --upgradable

# Veure nomes les de seguretat
apt list --upgradable 2>/dev/null | grep -i security

# Actualitzar tot
sudo apt upgrade

# Actualitzar tot, acceptant canvis "intrusius"
sudo apt full-upgrade

# Netejar paquets no usats
sudo apt autoremove
sudo apt autoclean

Per saber quins pegats de seguretat s'han aplicat:

cat /var/log/dpkg.log | grep "status installed" | grep security

Actualitzacions automatiques

El dilema classic: actualitzar pot trencar coses. La solucio son les actualitzacions automatiques amb control:

sudo apt install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

Configuracio a /etc/apt/apt.conf.d/50unattended-upgrades:

Unattended-Upgrade::Origins-Pattern {
    "origin=Debian,codename=${distro_codename},label=Debian-Security";
    "origin=Debian,codename=${distro_codename}-security,label=Debian-Security";
};

Unattended-Upgrade::Package-Blacklist {
    "vim";
    "nginx";
};

Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "03:00";
Unattended-Upgrade::Remove-Unused-Dependencies "true";
Unattended-Upgrade::Remove-New-Unused-Dependencies "true";
Unattended-Upgrade::Mail "bernat@bernatlab.cat";

Aixo aplica actualitzacions de seguretat automaticament a la nit, i reinicia el sistema si cal.

Dependabot: actualitzar imatges Docker

Si tens un repo de GitHub amb Docker Compose o Dockerfiles, pots activar Dependabot per obrir Pull Requests automaticament quan hi ha versions noves de les imatges.

.github/dependabot.yml:

version: 2
updates:
  - package-ecosystem: "docker"
    directory: "/"
    schedule:
      interval: "weekly"
    labels:
      - "dependencies"
      - "docker"
    open-pull-requests-limit: 5

Dependabot obrira PRs setmanalment. Tu les revisaries i fusionaries.

Watchtower i Diun: actualitzar contenidors

Watchtower actualitza automaticament les imatges:

docker run -d \
  --name watchtower \
  -v /var/run/docker.sock:/var/run/docker.sock \
  containrrr/watchtower \
  --cleanup \
  --schedule "0 0 4 * * *"

Diun nomes t'avisa quan hi ha actualitzacions, no les aplica:

docker run -d \
  --name diun \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e DIUN_WATCH_SCHEDULE="0 9 * * *" \
  -e DIUN_PROVIDERS_DOCKER=true \
  ghcr.io/crazy-max/diun:latest

Com saber quines imatges tenen CVEs

Eines com Trivy o Grype:

# Trivy
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy image bernatlab-api:latest

# Grype
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  anchore/grype:latest bernatlab-api:latest

Bones practiques amb actualitzacions

  • Aplica pegats de seguretat en 7-14 dies desde la publicacio.
  • Prova primer en una maquina de staging si tens serveis critics.
  • Fes backup abans d'actualitzar si la teva base de dades es critica.
  • Automatitza pero monitora: les actualitzacions automatiques son be, pero vull saber quan fallen.
  • Documenta les actualitzacions manuals al runbook.
  • No actualitzis el kernel sense provar: un kernel trencat pot deixar el sistema inutilitzable.

Actualitzar la propia RPi

sudo apt update
sudo apt full-upgrade
sudo rpi-update   # nomes si vols el firmware mes recent (pot ser inestable)

Per defecte, rpi-update no es recomanat perque porta el firmware mes recent pero menys provat.

Comandes utils

# Comprovar actualitzacions
sudo apt update
apt list --upgradable

# Veure pegats de seguretat
apt list --upgradable 2>/dev/null | grep -i security
sudo unattended-upgrade --dry-run

# Veure quins serveis s'han reiniciat per una actualitzacio
sudo needrestart

# Llistar versions d'un paquet
apt list --all-versions <paquet>

Conclusio

Mantenir el sistema actualitzat es la mesura de seguretat mes rendible: zero cost, zero esforç, i cobreix el 80% dels atacs coneguts. La combinacio unattended-upgrades + Dependabot + Watchtower (o Diun) et dona tranquilitat sense perdre el control.

🛠️ Exercici pràctic (30-45 min)

Configurar un sistema d'actualitzacions automatiques per al sistema operatiu, mes una estrategia d'actualitzacio de les imatges Docker.

Pas 1: Estat actual (5 min)

sudo apt update
apt list --upgradable | head -20
apt list --upgradable 2>/dev/null | grep -i security
sudo needrestart

Pas 2: Configura unattended-upgrades (15 min)

sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
sudo nano /etc/apt/apt.conf.d/50unattended-upgrades
sudo unattended-upgrade --dry-run

Pas 3: Correu (10 min)

sudo apt install -y msmtp msmtp-mta
sudo nano /etc/msmtprc
sudo chmod 600 /etc/msmtprc
echo "Prova" | mail -s "Test" bernat@bernatlab.cat

Pas 4: Dependabot (opcional) (10 min)

Crea .github/dependabot.yml amb configuracio setmanal.

Pas 5: Diun o Watchtower (10 min)

# Diun (nomes alerta)
docker run -d --name diun --restart always \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e DIUN_WATCH_SCHEDULE="0 9 * * *" \
  ghcr.io/crazy-max/diun:latest

# Watchtower (aplica automaticament)
docker run -d --name watchtower --restart always \
  -v /var/run/docker.sock:/var/run/docker.sock \
  containrrr/watchtower --cleanup --schedule "0 0 4 * * *"

Pas 6: Trivy (5 min)

docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy image homeassistant/home-assistant:stable
