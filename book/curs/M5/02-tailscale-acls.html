📖 Resum del capítol

La idea clau

Tailscale ens dona una xarxa privada (una VPN basada en WireGuard) entre tots els nostres dispositius. Pero Tailscale nomes es la meitat del joc: nomes connecta. Qui pot accedir a quines maquines, per quins ports, i en quines condicions, ho decideixen les ACLs. Una configuracio de Tailscale sense ACLs es com un edifici amb portes obertes a tothom que hi entra.

Que es Tailscale (repàs rapid)

Tailscale crea una xarxa privada entre els teus dispositius sense obrir ports al router. Utilitza WireGuard i un servidor de coordinacio per intercanviar claus.

# Instal·la a Debian/Ubuntu
curl -fsSL https://tailscale.com/install.sh | sh

# Arrenca
sudo tailscale up

# Estat
tailscale status

# IP assignada
tailscale ip -4

Cada maquina te una IP del rang 100.x.y.z. Entre elles es comuniquen xifrat punt a punt.

MagicDNS: noms en lloc d'IPs

Tailscale inclou un servei de DNS automatic anomenat MagicDNS:

# En lloc de ssh pi@100.64.0.1
ssh pi@raspberry

# O amb domini complet
ssh pi@raspberry.tailnet-xxxx.ts.net

Molt util per scripts i per accedir al servidor des de qualsevol lloc.

Que son les ACLs

Les ACLs (Access Control Lists) son regles que diuen a Tailscale "qui pot accedir a què". Son un fitxer en format HuJSON (JSON amb comentaris) que es penja a https://login.tailscale.com/admin/acls/file.

Exemple minimal:

{
  "acls": [
    {
      "action": "accept",
      "src": ["autogroup:members"],
      "dst": ["raspberry:22"]
    }
  ]
}

Aixo diu: "tots els membres del tailnet poden accedir al port 22 de raspberry". Tot el que no esta permes, esta denegat per defecte.

Anatomia d'una ACL

Una regla te quatre parts principals:

  • action: "accept" (permetre) o "deny" (bloquejar).
  • src: qui intenta accedir (usuari, grup, etiqueta).
  • dst: a quina maquina i port (format machine:port).
  • proto: protocol (tcp, udp, icmp). Per defecte tcp.

Exemple mes complet:

{
  "acls": [
    {
      "action": "accept",
      "src": ["autogroup:members"],
      "dst": [
        "raspberry:22",
        "raspberry:80,443",
        "raspberry:8123"
      ]
    },
    {
      "action": "deny",
      "src": ["*"],
      "dst": ["raspberry:*"]
    }
  ]
}

Etiquetes (tags): segmentacio per rol

Les etiquetes permeten agrupar maquines per funcio:

{
  "tagOwners": {
    "tag:server":   ["autogroup:admin"],
    "tag:iot":      ["autogroup:admin"],
    "tag:personal": ["autogroup:admin"]
  }
}

I despres fer regles tipus:

{
  "action": "accept",
  "src": ["tag:personal"],
  "dst": ["tag:server:22,80,443"]
}

Aixi, encara que algun dispositiu IoT sigui compromes, no pot accedir a la resta.

Com aplicar ACLs al BernatLab

  1. Ves a https://login.tailscale.com/admin/acls/file.
  2. Edita el fitxer amb les teves regles.
  3. Guarda. Tailscale aplica les noves regles en segons.

Exemple aplicat:

{
  "tagOwners": {
    "tag:server": ["autogroup:admin"],
    "tag:homelab": ["autogroup:admin"]
  },
  "acls": [
    {
      "action": "accept",
      "src": ["autogroup:admin"],
      "dst": ["tag:server:*"]
    },
    {
      "action": "accept",
      "src": ["user:marina@bernatlab.cat"],
      "dst": ["tag:server:22"]
    }
  ]
}

Bones practiques amb ACLs

  • Principi de minim privilege: dona nomes el que cada usuari necessita.
  • Etiqueta per funcio, no per maquina.
  • Documenta cada regla amb comentaris al HuJSON.
  • Audita periodicament cada 3 mesos.
  • No deixis "all ports" si no es absolutament necessari.
  • Combina amb ufw: les ACLs son una capa, el firewall una altra.

Comandes utils

# Estat general
tailscale status

# Ping a una maquina per Tailscale
tailscale ping raspberry

# Treure una maquina temporalment
sudo tailscale down

# Reactivar
sudo tailscale up

Conclusio: per que Tailscale + ACLs es la millor inversio

Si nomes poguessim triar una sola mesura de seguretat, seria aquesta. Perque:

  1. Amaga el servidor a Internet: el port 22 deixa d'estar obert al mon.
  2. Autenticacio forta nomes per a tu: cap altre IP pot intentar entrar.
  3. Zero configuracio de xarxa: no cal tocar el router.
  4. Funciona des de qualsevol lloc: cafe, hotel, mobil, igual.

🛠️ Exercici pràctic (30-45 min)

Configurar Tailscale a la RPi (si no ho tens), crear un grup d'etiquetes, i definir les ACLs mes adequades al BernatLab.

Pas 1: Verifica o instal·la Tailscale (5 min)

tailscale status 2>/dev/null || echo "No instal·lat"

# Si no
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale status

Pas 2: Dona d'alta una segona maquina (5 min)

Instal·la Tailscale al teu portatil o telefon. Verifica que es veuen entre elles:

tailscale ping portatil-bernat
tailscale ip

Pas 3: Crea les etiquetes (10 min)

Ves a https://login.tailscale.com/admin/acls/file. Canvia tagOwners:

{
  "tagOwners": {
    "tag:server":   ["autogroup:admin"],
    "tag:homelab":  ["autogroup:admin"],
    "tag:personal": ["autogroup:admin"]
  }
}

Guarda. Assigna tag:server a la RPi des de la consola (Edit machine).

Pas 4: Escriu les ACLs adequades (10 min)

{
  "tagOwners": {
    "tag:server":   ["autogroup:admin"],
    "tag:homelab":  ["autogroup:admin"],
    "tag:personal": ["autogroup:admin"]
  },
  "acls": [
    {
      "action": "accept",
      "src":    ["tag:personal"],
      "dst":    ["tag:server:22,80,443"]
    },
    {
      "action": "accept",
      "src":    ["tag:personal"],
      "dst":    ["tag:server:8123"]
    }
  ]
}

Guarda i prova:

# Hauria de funcionar
ssh bernat@raspberry
curl http://raspberry:8123

# Hauria de fallar
curl http://raspberry:3306

Pas 5: Documenta la configuracio (10 min)

Crea tailscale-acls.md amb:

  • IPs de cada maquina i la seva etiqueta
  • Captura de pantalla de la consola
  • Explicacio de cada regla
  • Data de la propera revisio

Validació

  • ☐ Tailscale esta actiu a la RPi i a un segon dispositiu.
  • ☐ Has creat les etiquetes (tag:server, tag:personal, etc.).
  • ☐ Les ACLs permeten nomes el que tu vols.
  • ☐ Pots accedir a la RPi des del portatil per Tailscale.
  • ☐ Has documentat la configuracio.
