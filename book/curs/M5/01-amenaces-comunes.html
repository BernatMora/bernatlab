📖 Resum del capítol

La idea clau

Una Raspberry Pi exposada a Internet (encara que sigui a traves de Tailscale) esta sotmesa a un flux constant d'amenaces automatitzades. No es paranoia: son bots que escanegen totes les adreces IP del planeta cada pocs minuts. Si el servidor te el port 22 obert, ja t'estan atacant, tant si ho veus com si no. Aquest capitol es per entendre quines son aquestes amenaces, com es manifesten, i quina es la superficie d'atac de la RPi del BernatLab.

La superficie d'atac del BernatLab

La "superficie d'atac" es el conjunt de punts per on un atacant podria entrar. A la nostra RPi, de partida es aquesta:

  • Port 22 (SSH): obert per defecte a totes les IP publiques.
  • Port 80/443 (HTTP/HTTPS): si hi ha un reverse proxy com Nginx o Caddy.
  • Serveis Dockers exposats: Home Assistant, Portainer, Gitea, etc.
  • Tailscale: xarxa privada WireGuard, pero si les ACLs son permissives, es una porta oberta igual.
  • Subdominis DNS: si tens un domini tipus bernatlab.cat, els bots el troben rapid.

A la practica, el risc mes gran es SSH, perque es l'entrada mes universal i on mes eines d'atac automatic existeixen.

SSH bruteforce: el perill numero 1

Un atac de bruteforce consisteix a provar milers de combinacions d'usuari i contrasenya fins a encertar la bona. Eines com Hydra, Medusa o SSHPass automatitzen el proces. Els bots mes sofisticats fan credential stuffing: proven combinacions conegudes que han fugit d'altres incidents.

Com es manifesta? Mira-ho tu mateix:

# Compta quants intents fallits ha tingut SSH desde l'inici
sudo journalctl -u ssh --no-pager | grep "Failed password" | wc -l

# Ultims 20 intents
sudo journalctl -u ssh -n 20 | grep "Failed"

# Usuaris mes intentats
sudo journalctl -u ssh --no-pager | grep "Failed password" | awk '{print $9}' | sort | uniq -c | sort -rn | head

En una RPi nova, en 24 hores pots tenir milers d'intents. Els mes comuns van contra root, pi, admin, ubuntu, user.

Ports oberts: el nmap dels dolents

Un cop un bot sap la teva IP, fa un port scan per veure quins serveis exposes. L'eina es diu nmap, i n'hi ha una versio "dolenta" que fan servir tots els scripts kiddies:

# El mateix que farien contra la teva RPi (desde un altre equip)
nmap -sV -p 1-1000 bernatlab.ddns.net

# Escaneig rapid dels 100 ports mes comuns
nmap -F bernatlab.ddns.net

Si el resultat es 22/tcp open ssh OpenSSH 9.2, ja saben on atacar. Per això un dels principis basics es no exposar mes del que cal. Cada port obert es un risc.

Vulnerabilitats conegudes: CVE

Quan es descobreix una fallada en un programa, se li assigna un identificador unic: el CVE (Common Vulnerabilities and Exposures). Com saber si el teu sistema te vulnerabilitats?

  • apt list --upgradable: paquets del sistema amb pegats nous.
  • docker scan bernatlab-api:latest: Trivy, Snyk per a imatges Docker.
  • Debian Security Tracker: security-tracker.debian.org.

No cal obsessionar-se, pero si tenir un sistema d'alertes basic: saber quan hi ha un pegat critic i aplicar-lo en dies, no en mesos.

Amenaces mes enlla del SSH

  • Exploits en aplicacions web: Home Assistant, Gitea, Nextcloud tenen la seva historia de CVEs.
  • Docker APIs exposades: mai exposar el socket de Docker sense autenticacio.
  • Credencials per defecte: canviar admin/admin de Home Assistant, Portainer, etc. immediatament.
  • Acces fisic: algú amb acces a la RPi pot extreure la SD i llegir les dades.

El model d'amenaca del BernatLab

Al BernatLab el model es:

  • Confidencialitat alta (dades de sensors, fitxers personals).
  • Integritat alta (backups no corromputs).
  • Disponibilitat mitjana (no es critic si la RPi cau 1 hora).
  • Atacant tipus: bots automatitzats, curiosos, possiblement algun script kiddie.
  • NO soc objectiu d'un APT: no cal paranoia de nivell estatal.

Aixo ens permet triar un nivell de seguretat bo pero no paranòic.

🛠️ Exercici pràctic (30-45 min)

Auditar l'estat actual de seguretat de la RPi del BernatLab: veure quins intents d'intrusio ha rebut, quins ports te oberts, i quin perfil d'amenaces tenim.

Pas 1: Inventari de serveis i ports (10 min)

# Tots els ports TCP oberts
sudo ss -tlnp

# Versio mes humana amb nom de servei
sudo ss -tlnp | awk 'NR>1 {print $4, $6}'

# Que esta escoltant nomes per IP
sudo lsof -i -P -n | grep LISTEN

Crea un fitxer inventari-seguretat.md al teu repo d'Obsidian amb el que has trobat.

Pas 2: Comptar els intents de login fallits (10 min)

# Total d'intents fallits
sudo journalctl -u ssh --no-pager | grep "Failed password" | wc -l

# Ultims 50 intents
sudo journalctl -u ssh --no-pager | grep "Failed password" | tail -50

# Top 10 usuaris mes intentats
sudo journalctl -u ssh --no-pager | grep "Failed password" | awk '{print $9}' | sort | uniq -c | sort -rn | head

# Adreces IP dels atacants (top 20)
sudo journalctl -u ssh --no-pager | grep "Failed password" | awk '{print $11}' | sort | uniq -c | sort -rn | head -20

Pas 3: Escanejar la teva propia maquina (10 min)

sudo apt install -y nmap

# Escaneig basic dels 1000 ports mes comuns
nmap localhost

# Escaneig amb deteccio de versio
nmap -sV localhost

# Si tens Tailscale actiu
tailscale ip -4
nmap $(tailscale ip -4)

Pas 4: Buscar patrons sospitosos (10 min)

# Logins exitosos
sudo last -20

# Logins fallits
sudo lastb -20

# Autenticacions SSH exitoses
sudo journalctl -u ssh | grep "Accepted"

# Usuaris amb shell interactiva
grep -v "nologin\|false" /etc/passwd

# Processos actius sospitosos
ps auxf | head -50

# Connexions xarxa actives cap a fora
sudo ss -tnp | grep ESTAB

Pas 5: Redacta el baseline (5 min)

Al fitxer inventari-seguretat.md, escriu una seccio "Baseline" amb:

  • Data i hora de l'auditoria
  • Versio del sistema (cat /etc/os-release)
  • Versio del kernel (uname -r)
  • Llista de serveis i ports
  • Total d'intents SSH fallits
  • Adreces IP atacants principals
  • Connexions actives actuals
  • Conclusions: quines son les prioritats

Validació

  • ☐ Has fet un inventari complet de serveis i ports oberts.
  • ☐ Has comptabilitzat els intents de login fallits.
  • ☐ Has identificat els usuaris mes atacats.
  • ☐ Has fet un escaneig amb nmap i l'has comparat amb l'inventari.
  • ☐ Has creat el document inventari-seguretat.md amb el baseline.

Resum ràpid

  1. Bruteforce = provar milers de contrasenyes automaticament.
  2. Port 22 es el port per defecte de SSH.
  3. Superficie d'atac = punts d'entrada potencials al sistema.
  4. Usuari pi es el mes atacat a la RPi (compte per defecte).
  5. CVE = Common Vulnerabilities and Exposures.
  6. Comanda = sudo lastb.
  7. Menys ports = menys vectors d'entrada.
  8. Eina = nmap.
