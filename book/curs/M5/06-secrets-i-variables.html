📖 Resum del capítol

La idea clau

Qualsevol cadena de text que permeti a algú accedir a una cosa que no hauria es un secret: contrasenyes, claus API, tokens, certificats privats, claus SSH privades. La gestio d'aquests secrets es un dels punts mes critics de la seguretat del servidor. Si es filtren, tota la resta de defenses queden inutilitzades. Al BernatLab tenim tres opcions: fitxers .env, Docker secrets, i vaults (com Vaultwarden, Ansible Vault).

Que es un secret

Un secret es qualsevol dada que volem mantenir confidencial perque dona acces a alguna cosa. Els mes comuns:

  • Contrasenyes de serveis (Home Assistant, Portainer, base de dades).
  • Claus API (Tailscale, OpenWeather, Stripe, etc.).
  • Tokens de bots (Telegram, Discord).
  • Claus privades SSH.
  • Certificats TLS privats.
  • Contrasenyes de wifi.

L'error mes gran: secrets al codi

L'error mes frequent i mes greu es posar secrets al codi font:

# NO FACIS MAI AIXO
db_password = "supersecret123"
api_key = "sk-abcdefghijklmnop"

Si aquest codi va a un repositori Git (encara que sigui privat), es considera compromes. Perque Git guarda tot l'historial. Un cop filtrat, un secret es considera cremat per sempre.

Fitxers .env: el minim acceptable

La manera mes simple de gestionar secrets al homelab es amb un fitxer .env:

# /opt/homelab/.env
DB_PASSWORD=supersecret123
API_KEY=sk-abcdefghijklmnop
TELEGRAM_TOKEN=123456:ABC-DEF

Aquest fitxer mai va al git. S'afegeix al .gitignore:

echo ".env" >> .gitignore

Bones practiques amb .env

  • MAI al git. Afegeix .env a .gitignore SEMPRE.
  • Permissos 600: nomes tu pots llegir. chmod 600 .env.
  • Un .env per entorn: .env.dev, .env.prod.
  • Documenta les variables al .env.example (que SI va al git):
# .env.example (al git, sense valors reals)
DB_PASSWORD=changeme
API_KEY=your_api_key_here

Docker secrets

Docker Swarm te un sistema natiu de secrets: emmagatzema una cadena xifrada i la passa nomes als contenidors autoritzats:

echo "supersecret123" | docker secret create db_password -

Al compose:

services:
  db:
    image: postgres
    secrets:
      - db_password
    environment:
      POSTGRES_PASSWORD_FILE: /run/secrets/db_password

secrets:
  db_password:
    external: true

Vaults: gestio centralitzada

Un vault es un servei centralitzat per emmagatzemar secrets amb xifratge fort, auditoria, i acces granular:

  • HashiCorp Vault: el mes complet, pero complexe.
  • Bitwarden / Vaultwarden: gestor de contrasenyes amb auto-hostatjament. Ideal per al BernatLab.
  • Passbolt: similar a Vaultwarden.
  • Ansible Vault: xifra fitxers YAML amb una contrasenya.

Vaultwarden:

docker run -d --name vaultwarden \
  -v /vw-data/:/data/ \
  -p 8080:80 \
  vaultwarden/server:latest

Com accedir als secrets al runtime

Patrons comuns:

  • Variable d'entorn: os.environ["DB_PASSWORD"].
  • Docker secret: obrir /run/secrets/db_password.
  • API del vault: crida HTTP al vault.

Exemple amb bash:

#!/bin/bash
set -a
source /opt/homelab/.env
set +a

# Usar les variables
echo "Database: $DB_PASSWORD"

Bones practiques generals

  • Mai al git. Mai.
  • Mai en captures de pantalla. Mai.
  • Mai en xats o correus. Mai.
  • Rotacio periodica: canvia els secrets cada 3-6 mesos.
  • Minim privilege: cada servei te nomes el secret que necessita.
  • Auditoria: revisa quins secrets hi ha, on son, i qui te acces.
  • Generadors de contrasenyes: openssl rand.
# Generar contrasenyes segures
openssl rand -base64 32
pwgen 16 1
openssl rand -hex 32

Comandes utils

# Comprovar que un .env no es al git
git check-ignore .env

# Veure l'historial per possibles fuites
git log -p | grep -iE "password|token|secret" | head

# Generar una contrasenya forta
openssl rand -hex 32

# Auditar permisos dels fitxers .env
find /opt -name ".env" -type f -exec ls -l {} \;

Conclusio

La gestio de secrets es la practica mes critica de la seguretat. Una contrasenya filtrada inutilitza totes les altres defenses. Per tant:

  1. Mai al codi ni al git.
  2. Sempre en un fitxer amb permisos restrictius o un vault.
  3. Sempre amb rotacio periodica.
  4. Sempre amb un generador aleatori.

🛠️ Exercici pràctic (30-45 min)

Auditar i securitzar la gestio de secrets al BernatLab: identificar secrets exposats, moure'ls a fitxers .env, i (opcionalment) configurar Vaultwarden.

Pas 1: Audita els teus secrets actuals (10 min)

find /opt /home -name ".env*" -type f 2>/dev/null
grep -rE "(password|token|api_key|secret)\s*=\s*['\"]" /opt /home 2>/dev/null | head -20
cd /opt/homelab
git log -p | grep -iE "password|token|api_key" | head -20

Pas 2: Mou a un .env (10 min)

mkdir -p /opt/homelab
cd /opt/homelab
touch .env
chmod 600 .env
nano .env

Crea un .env.example per al git, i afegeix .env al .gitignore.

Pas 3: Comprova que .env no va al git (5 min)

git check-ignore -v .env
git add .env  # hauria de fallar
git add .env.example  # hauria de funcionar

Pas 4: Carrega les variables (10 min)

Adapta el docker-compose.yml per fer servir env_file. Carrega amb `source` als scripts bash.

Pas 5: Vaultwarden (opcional) (10 min)

mkdir -p /opt/vaultwarden/data
docker run -d --name vaultwarden \
  -v /opt/vaultwarden/data:/data \
  -p 8080:80 \
  vaultwarden/server:latest

Pas 6: Genera contrasenyes noves (5 min)

openssl rand -base64 24 | tr -d "=+/" | cut -c1-20

Validació

  • ☐ Has auditat on tens secrets actualment.
  • ☐ Has mogut tots els secrets a un .env amb permisos 600.
  • ☐ Tens un .env.example al git.
  • ☐ El .env real NO esta al git.
  • ☐ Les aplicacions carreguen correctament les variables.
  • ☐ Has generat contrasenyes noves.

Resum ràpid

  1. Secret = dada confidencial que dona acces.

  3. .env = fitxer amb variables d'entorn.
  4. .gitignore = tots els .env sempre.
  5. Vault = servei centralitzat de secrets.

  7. openssl rand -base64 32 = generar.
  8. .env.example = plantilla buida al git.
