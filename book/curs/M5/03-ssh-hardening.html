📖 Resum del capítol

La idea clau

SSH es la porta d'entrada al servidor. Si un atacant entra per aqui, te control absolut. Per tant, hem de posar totes les barreres possibles: nomes autenticacio amb claus, port personalitzat per reduir soroll, fail2ban per bloquejar atacs automatitzats, i limitacions per evitar escalades. Es la mesura mes important despres de Tailscale.

Per que SSH es un objectiu prioritari

Tot i que Tailscale amaga el port 22, SSH continua sent el servei mes critic:

  • Es l'entrada a la consola: shell d'administracio.
  • Te permisos de superusuari: un sudo et dona tot el control.
  • Es universal: qualsevol Linux te SSH.
  • Es el que mes saben atacar els bots.

Desactivar el login amb contrasenya

Aixo es la mesura mes important. Per defecte OpenSSH accepta contrasenyes i claus. Si nomes acceptes claus, els atacs de bruteforce fallen sempre.

# 1. Genera una clau forta (CLIENT, no servidor)
ssh-keygen -t ed25519 -C "bernat@bernatlab"

# 2. Copia la clau publica al servidor
ssh-copy-id -i ~/.ssh/id_ed25519.pub bernat@raspberry

# 3. Desactiva les contrasenyes
sudo nano /etc/ssh/sshd_config

Edita /etc/ssh/sshd_config:

PubkeyAuthentication yes
PasswordAuthentication no
ChallengeResponseAuthentication no
AuthenticationMethods publickey

Aplica:

sudo sshd -t   # valida la sintaxi
sudo systemctl restart sshd

IMPORTANT: obre una segona sessio SSH abans de tancar la primera.

Desactivar root login

L'usuari root te permisos absoluts. No cal que un atacant hi entri directament.

PermitRootLogin no

Alternatives: prohibit-password (nomes claus) o forced-commands-only (nomes per scripts).

Canviar el port

Port 5022

El 95% dels bots nomes miren el port 22. Pero no es seguretat per si sola: un nmap el trobara. Es reduccio de soroll, no seguretat.

fail2ban: el vigilant

fail2ban llegeix els logs i bloqueja IPs que fan massa intents fallits.

sudo apt install fail2ban
sudo nano /etc/fail2ban/jail.local

Contingut:

[DEFAULT]
ignoreip = 127.0.0.1/8 100.64.0.0/10
maxretry = 5
findtime = 600
bantime = 3600
banaction = ufw

[sshd]
enabled = true
port    = ssh
filter  = sshd
logpath = %(sshd_log)s

Activar i veure:

sudo systemctl enable fail2ban
sudo systemctl start fail2ban
sudo fail2ban-client status sshd

# IPs bloquejades
sudo fail2ban-client status sshd | grep "Banned IP list"

# Desbloquejar manualment
sudo fail2ban-client set sshd unbanip 1.2.3.4

Configuracio completa recomanada

# /etc/ssh/sshd_config
Port 5022
AddressFamily inet
Protocol 2

PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
ChallengeResponseAuthentication no
AuthenticationMethods publickey
MaxAuthTries 3
LoginGraceTime 30
MaxSessions 3

X11Forwarding no
AllowTcpForwarding no
GatewayPorts no
PermitUserEnvironment no

AcceptEnv LANG LC_*
Banner /etc/issue.net

Com verificar la configuracio

sudo sshd -t               # valida sintaxi
sudo sshd -T | head -30    # configuracio efectiva
sudo sshd -T | grep authorizedkeys

ssh -p 5022 -v bernat@raspberry

Bones practiques

  • Mai canviïs la configuracio amb una sola sessio oberta. Sempre dues.
  • sudo sshd -t abans de reiniciar.
  • Copia de seguretat abans d'editar.
  • Tens una consola fisica com a salvavides.
  • Revisa els logs setmanalment.

Conclusio: el triple combo

SSH fort = Tailscale (amaga) + claus (autenticacio) + fail2ban (vigila). Si tens aquestes tres coses, es quasi impossible que un atacant pugui entrar per SSH.

🛠️ Exercici pràctic (30-45 min)

Endurir el servei SSH de la RPi: desactivar contrasenyes, canviar el port, instal·lar fail2ban, i verificar que tot funciona.

Pas 1: Assegura la teva clau (5 min)

ssh bernat@raspberry "cat ~/.ssh/authorized_keys"
ssh-keygen -t ed25519 -C "bernat-backup@bernatlab"
ssh-copy-id -i ~/.ssh/id_ed25519_backup.pub bernat@raspberry

Pas 2: Fes una copia de seguretat (5 min)

sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
sudo cp -r /etc/ssh /etc/ssh.bak

Pas 3: Aplica la nova configuracio (10 min)

Edita /etc/ssh/sshd_config:

Port 5022
AddressFamily inet
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
ChallengeResponseAuthentication no
AuthenticationMethods publickey
MaxAuthTries 3
LoginGraceTime 30
MaxSessions 3
X11Forwarding no
AllowTcpForwarding no
GatewayPorts no
AcceptEnv LANG LC_*

IMPORTANT: obre una SEGONA sessio SSH.

Pas 4: Valida i reinicia (5 min)

sudo sshd -t
sudo sshd -T | grep -E "port|permitroot|password|pubkey|authmethods"
sudo systemctl restart sshd
sudo systemctl status sshd

Pas 5: Verifica la nova connexio (5 min)

ssh -p 5022 bernat@raspberry
ssh -p 5022 -v bernat@raspberry 2>&1 | grep -i "auth"

# Comprova que la contrasenya NO funciona
sshpass -p "wrong" ssh -p 5022 -o PubkeyAuthentication=no bernat@raspberry

Pas 6: Instal·la i configura fail2ban (10 min)

sudo apt install -y fail2ban
sudo nano /etc/fail2ban/jail.local
[DEFAULT]
ignoreip = 127.0.0.1/8 100.64.0.0/10
maxretry = 5
findtime = 600
bantime = 3600
banaction = ufw

[sshd]
enabled = true
port    = ssh
filter  = sshd
logpath = %(sshd_log)s
sudo systemctl enable fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd

Resum ràpid

  1. Hardening = aplicar mesures addicionals.
  2. PermitRootLogin no = no login directe com a root.
  3. ssh-keygen -t ed25519 = generar claus modernes.
  4. PasswordAuthentication no = nomes claus.
  5. fail2ban = bloqueja IPs amb massa intents fallits.
  6. Canviar port = nomes reduccio de soroll.
  7. MaxAuthTries = maxim d'intents per sessio.
  8. ~/.ssh/authorized_keys = on posem la clau publica.
