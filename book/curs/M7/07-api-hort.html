📖 Resum del capítol

La idea clau

L'API REST es el pont entre les dades guardades (InfluxDB, PostgreSQL) i el mon exterior. Es una interficie HTTP amb verbs estandard (GET, POST, PUT, DELETE) que respon amb JSON. A l'Hort Osona la implementem amb Flask.

Que es una API REST

  • Recursos per URLs: /api/v1/sensors/1B32.
  • Verbs HTTP: GET (llegir), POST (crear), PUT (actualitzar), DELETE.
  • Stateless: cada peticio es independent.
  • JSON per a respostes.

Per que Flask

API de 5-15 endpoints, l'equip ja el coneix, ecosistema madur. Alternatives: FastAPI (mes modern), Django REST (overkill), Bottle (massa minimalista).

Estructura dels endpoints

/api/v1/
  /sensors
    GET    /sensors/                   -> llista tots els sensors
    GET    /sensors/<id>              -> info d'un sensor
    GET    /sensors/<id>/latest       -> ultima lectura
    GET    /sensors/<id>/history?h=24 -> historic
  /sectors
    GET    /sectors                    -> sectors de l'hort
    GET    /sectors/<id>/summary
  /calendar
    GET    /calendar/<year>/<month>
    POST   /calendar/events
  /alerts
    GET    /alerts/active
    POST   /alerts/acknowledge/<id>

Exemple d'endpoint

@app.route("/api/v1/sensors/<device_id>/latest", methods=["GET"])
@require_api_key
def get_sensor_latest(device_id):
    flux = f'''
    from(bucket: "hort-osona")
      |> range(start: -1h)
      |> filter(fn: (r) => r.device == "{device_id}")
      |> last()
    '''
    result = query_api.query(flux)
    if not result or not result[0].records:
        return jsonify({"error": "No data"}), 404
    data = {"device": device_id, "ts": None, "fields": {}}
    for record in result[0].records:
        data["ts"] = record.get_time().isoformat()
        data["fields"][record.get_field()] = record.get_value()
    return jsonify(data), 200

CORS: el pont entre origens

Si la PWA esta a github.io i l'API a la teva RPi, el navegador bloqueja. Solucio amb flask-cors:

from flask_cors import CORS
CORS(app, origins=["https://hort-osona.github.io", "http://localhost:*"])

Autenticacio: API key

Decorator que valida el header X-API-Key:

def require_api_key(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        key = request.headers.get("X-API-Key")
        if not key or key != API_KEY:
            return jsonify({"error": "Unauthorized"}), 401
        return f(*args, **kwargs)
    return decorated

🛠️ Exercici pràctic (40-60 min)

Construir una API REST amb Flask que llegeix d'InfluxDB i exposa 4 endpoints: /sensors, /sensors/<id>/latest, /sensors/<id>/history, i /health.

Pas 1: Prepara el projecte (5 min)

mkdir -p ~/hort-osona/api && cd ~/hort-osona/api
python3 -m venv .venv && source .venv/bin/activate
pip install flask flask-cors influxdb-client gunicorn python-dotenv

Crea .env amb HORT_API_KEY=hort-osona-test-key-2026 i CORS_ORIGINS.

Pas 2: L'API basica (15 min)

Script app.py amb 4 endpoints, decorator require_api_key, helper run_query i una llista hardcoded de sectors.

Pas 3: Prova l'API (5 min)

python3 app.py
# En una altra terminal:
curl http://localhost:5000/api/v1/health
curl -H "X-API-Key: hort-osona-test-key-2026" http://localhost:5000/api/v1/sectors
curl -H "X-API-Key: hort-osona-test-key-2026" http://localhost:5000/api/v1/sensors/miflora-1B32/latest
curl -H "X-API-Key: hort-osona-test-key-2026" "http://localhost:5000/api/v1/sensors/miflora-1B32/history?h=168&field=soil_moisture&window=1h"

Pas 4: Dockerfile i docker-compose (10 min)

Dockerfile amb python:3.12-slim i gunicorn (2 workers, port 5000). Afegeix al docker-compose.yml amb env_file i depends_on: influxdb.

Pas 5: Documentacio OpenAPI (10 min)

Crea openapi.yaml amb la definicio dels 4 endpoints, parametres, security (ApiKey) i respostes. Visualitza-la a https://editor.swagger.io.

Pas 6: Tests amb pytest (10 min)

Script test_app.py amb 4 tests: health (no auth), sectors (sense i amb API key), sector not found. Executa amb pytest -v.
