📖 Resum del capítol

La idea clau

L'Hort Osona te una arquitectura modular: cada peça fa una cosa i la fa be, i totes es comuniquen a traves d'un bus de missatges (MQTT). Es el patro pipe-and-filter. Si una peça falla, la resta continua.

El pipeline de dades

El flux te 6 etapes:

Sensors -> Gateway -> MQTT broker -> Processadors -> Emmagatzematge -> API/Web
MiFlora    RPi         Mosquitto     Python/Node      InfluxDB      PWA
BME280     ESP32                     InfluxDB-relay   PostgreSQL    GitHub
LoRa       gateway                                   MinIO         Pages

Per que MQTT i no HTTP

  • Push en lloc de pull: el sensor publica, el broker distribueix.
  • Desacoblat: el sensor no sap qui consumeix les seves dades.
  • QoS: pots garantir que el missatge arriba.
  • LWT: pots saber si un sensor ha caigut.
  • Buffer integrat: si el consumidor esta offline, el broker retè els missatges.
  • Topic-based routing: pots subscriure't nomes als missatges que t'interessen.

Les capes de software (Docker)

A l'Hort Osona cada servei es un contenidor Docker. Exemple de docker-compose.yml amb Mosquitto, InfluxDB, mqtt-to-influx i Grafana.

La RPi central

Una RPi 4B (4 GB) corre Mosquitto, InfluxDB, PostgreSQL, MinIO, Flask API, gateways i Grafana. Molts serveis en una sola maquina, pero tots llegers (Mosquitto 30 MB, Grafana 200 MB).

Alta disponibilitat

Capes de tolerancia a falles:

  1. Sensor: pila nova o recanvi.
  2. Gateway: si cau, missatges es perden (BLE sense buffer).
  3. Mosquitto: te buffer a disc.
  4. InfluxDB: te WAL (write-ahead log).
  5. API/PWA: si cau, dades segueixen entrant.

El pitjor cas es la RPi central. Solucio: SSD extern, backups diaries, mini PC o segona RPi per failover.

Patrons de procesament

  • Pipeline: sensor -> MQTT -> InfluxDB.
  • Fan-out: un missatge a multiples consumidors (InfluxDB + alerta + PWA).
  • Fan-in: multiples sensors agregats (e.g. temperatura mitjana de l'hort).

Connexions amb altres capitols

  • M7 Cap 2, 3 - Sensors concrets que alimenten el pipeline.
  • M7 Cap 5 - MQTT es el bus central.
  • M7 Cap 6 - InfluxDB es on acaben les dades.
  • M7 Cap 7 - L'API exposa les dades a la web.
  • M7 Cap 8 - La PWA consumeix l'API.

🛠️ Exercici pràctic (40-60 min)

Muntar l'arquitectura completa en local amb Docker Compose: Mosquitto + InfluxDB + script Python que escolta MQTT i escriu a InfluxDB.

Pas 1: Estructura del projecte (5 min)

mkdir -p ~/hort-osona/{mosquitto/config,mosquitto/data,influxdb,scripts,grafana,api}
cd ~/hort-osona

Pas 2: Configura Mosquitto (5 min)

Crea mosquitto/config/mosquitto.conf amb persistence true, port 1883, password_file, i log a stdout.

Pas 3: Crea el docker-compose.yml (10 min)

Defineix serveis: mosquitto (eclipse-mosquitto:2), influxdb (2.7 amb init org/bucket/retention 30d), mqtt-to-influx (build local), grafana (10.4).

Pas 4: Crea el servei mqtt-to-influx (15 min)

Script Python que subscriu a hort-osona/#, parseja el JSON, construeix un Point d'InfluxDB amb tags device i topic, i l'escriu amb WriteOptions de batch.

Pas 5: Publica dades de prova (5 min)

mosquitto_pub -h localhost -p 1883 -u hort-osona -P secretpass \
   -t "hort-osona/miflora/1B32" \
   -m '{"device":"miflora-1B32","ts":"2026-04-12T12:00:00Z","soil_moisture":42,"soil_temp_c":18.5,"ec_us_cm":820,"lux":18000,"battery":87}'
docker compose logs -f mqtt-to-influx

Pas 6: Verifica amb InfluxDB i Grafana (5 min)

docker compose exec influxdb influx query \
   'from(bucket:"hort-osona") |> range(start:-1h) |> filter(fn: (r) => r._measurement == "miflora")' \
   --org bernatlab

Configura Grafana a http://<ip-rpi>:3000 amb data source InfluxDB i un dashboard basc.

Validació

  • ☐ Has aixecat 4 serveis amb docker compose up.
  • ☐ Has publicat un missatge amb mosquitto_pub.
  • ☐ El servei mqtt-to-influx ha escrit el punt a InfluxDB.
  • ☐ Has verificat amb influx query.
  • ☐ Has configurat Grafana per visualitzar.
