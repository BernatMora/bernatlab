📖 Resum del capítol

La idea clau

Al BernatLab quasi totes les dades viuen dins de contenidors Docker: Grafana té els seus dashboards, InfluxDB té les lectures de sensors, Mosquitto té la configuració del broker MQTT, Nextcloud té els fitxers dels usuaris. Si no fas backup dels volums d'aquests contenidors, quan la RPi mori o la SD es corrompi, perds totes les dades.

La bona notícia és que fer backup dels volums Docker és relativament senzill un cop entens la diferència entre volums natius (els gestiona Docker) i bind mounts (els gestionaries tu). Els dos es poden backupejar, però el mètode canvia lleugerament.

On són les dades dins Docker?

Docker emmagatzema les dades dels seus contenidors de dues maneres:

Volums natius

Docker els gestiona a /var/lib/docker/volumes/. Exemple:

volumes:
  - grafana-data:/var/lib/grafana

Avantatges: Docker els pot moure, fer backup amb un sol comando.
Desavantatges: menys transparents.

Bind mounts

Tu especifiques una ruta de l'amfitrió:

volumes:
  - /home/pi/bernatlab/grafana:/var/lib/grafana

Avantatges: transparents, pots navegar-hi amb ls.
Desavantatges: la responsabilitat de backups és teva.

Quin mètode al BernatLab?

Al BernatLab faig servir bind mounts per quasi tot. Són més transparents, puc navegar per /home/pi/bernatlab/... i veure exactament quines dades tinc. A més a més, els backup amb rsync/restic són trivials: són simplement fitxers en un directori.

Només faig servir volums natius per a casos molt específics on el rendiment és crític (per exemple, la base de dades d'InfluxDB té més rendiment amb un volum natiu que amb un bind mount a la SD).

Mètodes de backup

Mètode 1: Aturar el contenidor i copiar

docker stop grafana
sudo tar -czf backup-grafana-$(date +%Y%m%d).tar.gz \
  /var/lib/docker/volumes/grafana-data/_data/
docker start grafana

Mètode 2: Contenidor temporal

docker run --rm \
  -v grafana-data:/source:ro \
  -v /tmp/backup:/backup \
  alpine tar -czf /backup/grafana-$(date +%Y%m%d).tar.gz -C /source .

Backups consistents de bases de dades

Aquí rau la trampa. Si fas tar d'un directori de PostgreSQL mentre el servidor està escrivint, el backup pot quedar inconsistent. La solució és fer un dump lògic:

# Per a PostgreSQL
docker exec postgres pg_dump -U bernatlab bernatlab | \
  gzip > /home/pi/bernatlab/backups/postgres-$(date +%Y%m%d).sql.gz

# Per a MySQL/MariaDB
docker exec mysql mysqldump -u root -p$MYSQL_ROOT_PASSWORD bernatlab | \
  gzip > /home/pi/bernatlab/backups/mysql-$(date +%Y%m%d).sql.gz

Estratègia al BernatLab

Al BernatLab tinc un script /home/pi/bernatlab/scripts/backup-volums.sh que:

  1. Fa un pg_dump de PostgreSQL comprimit.
  2. Fa un dump d'InfluxDB.
  3. Fa un tar dels bind mounts importants (Grafana, Mosquitto, Nextcloud).
  4. Guarda tot a /home/pi/bernatlab/backups/.
  5. Deixa que restic s'encarregui de copiar-ho al núvol.

Això s'executa cada nit a les 2 de la matinada amb un cron.

Restauració

Restaurar és la part més important. Si no proves mai de restaurar, el teu backup no serveix per a res. Periòdicament (un cop al mes) hauries de:

  1. Agafar un backup recent.
  2. Aixecar un contenidor de prova amb ell.
  3. Verificar que les dades són correctes.
  4. Esborrar el contenidor de prova.

Això és el DR test (Disaster Recovery test).

🛠️ Exercici pràctic (30-40 min)

Practicar el backup i la restauració d'un volum Docker real amb PostgreSQL.

Pas 1: Crea un contenidor de prova (5 min)

docker volume create pg-prova
docker run -d --name pg-prova \
  -e POSTGRES_PASSWORD=prova123 \
  -e POSTGRES_DB=hivernacle \
  -v pg-prova:/var/lib/postgresql/data \
  postgres:16-alpine
sleep 10
docker ps | grep pg-prova

Pas 2: Omple'l amb dades (5 min)

docker exec -it pg-prova psql -U postgres -d hivernacle -c "
  CREATE TABLE sensors (
    id SERIAL PRIMARY KEY,
    nom TEXT,
    valor REAL,
    ts TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
  INSERT INTO sensors (nom, valor) VALUES
    ('temperatura', 22.5),
    ('humitat', 65.0),
    ('llum', 850.0);
"
docker exec -it pg-prova psql -U postgres -d hivernacle -c "SELECT * FROM sensors;"

Pas 3: Fes un dump lògic (10 min)

mkdir -p /home/pi/bernatlab/backups/prova
docker exec pg-prova pg_dump -U postgres hivernacle | \
  gzip > /home/pi/bernatlab/backups/prova/hivernacle-$(date +%Y%m%d).sql.gz
ls -lh /home/pi/bernatlab/backups/prova/
zcat /home/pi/bernatlab/backups/prova/hivernacle-*.sql.gz | head -30

Pas 4: Copia del volum amb tar (5 min)

docker stop pg-prova
sudo tar -czf /home/pi/bernatlab/backups/prova/volum-pg-$(date +%Y%m%d).tar.gz \
  /var/lib/docker/volumes/pg-prova/_data/
ls -lh /home/pi/bernatlab/backups/prova/
docker start pg-prova

Pas 5: Simula un desastre (5 min)

docker rm -f pg-prova
docker volume rm pg-prova
docker ps -a | grep pg-prova
docker volume ls | grep pg-prova

Pas 6: Restaura des del dump (10 min)

docker volume create pg-prova-restaurat
docker run -d --name pg-restaurat \
  -e POSTGRES_PASSWORD=prova123 \
  -e POSTGRES_DB=hivernacle \
  -v pg-prova-restaurat:/var/lib/postgresql/data \
  postgres:16-alpine
sleep 10
zcat /home/pi/bernatlab/backups/prova/hivernacle-*.sql.gz | \
  docker exec -i pg-restaurat psql -U postgres -d hivernacle
docker exec -it pg-restaurat psql -U postgres -d hivernacle -c "SELECT * FROM sensors;"

Pas 7: Neteja

docker stop pg-restaurat
docker rm pg-restaurat
docker volume rm pg-prova-restaurat

Validació

  • ☐ Has creat un contenidor PostgreSQL amb dades reals.
  • ☐ Has fet un dump consistent amb pg_dump | gzip.
  • ☐ Has entès per què el tar directe és perillós per a BD actives.
  • ☐ Has "perdut" el contenidor i el volum a propòsit.
  • ☐ Has restaurat el dump i has vist les dades originals.
  • ☐ Has après la diferència entre "tinc backup" i "tinc un backup que funciona".

Resum ràpid

  1. Volums natius = /var/lib/docker/volumes.
  2. Volum vs bind mount = Docker gestiona vs tu tries ruta.
  3. tar a BD activa = inconsistent.
  4. Dump PG = docker exec postgres pg_dump.
  5. Sense aturar = contenidor temporal --rm.
  6. DR test = Disaster Recovery test.
  7. BernatLab = bind mounts a /home/pi/bernatlab/.
  8. NO bo per BD = copiar fitxers mentre el servidor escriu.
