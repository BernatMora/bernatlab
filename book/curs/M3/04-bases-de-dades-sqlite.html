📖 Resum del capítol

La idea clau

SQLite és la base de dades més usada del món, i probablement no ho sabies. Està al teu telèfon Android, al teu navegador Chrome, al teu sistema operatiu, a milers d'aplicacions. I el més important: és un sol fitxer. No hi ha cap servidor, cap dimoni, cap port. És la BD més simple que pots fer servir, i alhora prou potent per a molts casos reals.

Al BernatLab la faig servir per a totes les dades petites i locals: historial de tasques, registres de configuració, metadades de sensors, cache de consultes. Per a dades més grans o amb més concurrència faig servir PostgreSQL (cap 5) o InfluxDB (cap 6).

Què és SQLite exactament?

És una base de dades embeguda (embedded):

  • No és un servidor que escolta en un port.
  • És una llibreria que la teva aplicació enllaça.
  • La BD és un sol fitxer al sistema de fitxers.
  • Un sol fitxer per aplicació, normalment a /var/lib/ o /home/pi/.

Exemple típic al BernatLab:

/home/pi/bernatlab/notes/quadern-camp.db
/var/lib/homeassistant/home-assistant_v2.db

Per què SQLite és tan popular?

  1. Simplicitat: no cal instal·lar ni configurar res.
  2. Fiabilitat: una de les BD més testejades del món.
  3. Rendiment: per a aplicacions petites, més ràpid que PostgreSQL.
  4. Portabilitat: el fitxer es pot copiar a un USB.
  5. ACID: compleix Atomicity, Consistency, Isolation, Durability.
  6. Sense cost: és public domain.

Quan usar SQLite

SQLite brilla en aquests casos:

  • Aplicacions locals (sense servidor).
  • Dispositius mòbils i IoT.
  • Prototips i MVPs.
  • Cache i configuració.
  • Fins a milers d'escriptures per segon en condicions ideals.

Quan NO usar SQLite

SQLite té límits clars:

  • Escriptures concurrents: només una a la vegada.
  • Volum de dades: per sobre d'1-2 GB comença a ser menys eficient.
  • Xarxa: només local, no es pot accedir per xarxa directament.
  • Replicació: no té master-slave ni clustering.

Eines per treballar amb SQLite

sqlite3 (línia de comandes)

sqlite3 hivernacle.db

.tables
.schema sensors
.headers on
.mode column
SELECT * FROM sensors LIMIT 5;
.quit

DB Browser for SQLite (gràfic)

Eina gràfica multiplataforma. Permet veure l'esquema, navegar dades, fer consultes amb resaltat de sintaxi, exportar a CSV/JSON.

sudo apt install sqlitebrowser
sqlitebrowser hivernacle.db &

Com fer backup d'una BD SQLite

Mètode 1: .dump (lògic, recomanat)

sqlite3 hivernacle.db .dump > hivernacle-$(date +%Y%m%d).sql

Genera un fitxer SQL amb totes les sentències CREATE i INSERT. Es pot restaurar a qualsevol altre SQLite.

Mètode 2: Copiar el .db (només si la BD està quieta)

sudo systemctl stop home-assistant
cp /var/lib/homeassistant/home-assistant_v2.db \
   /home/pi/bernatlab/backups/
sudo systemctl start home-assistant

Important: mai copiïs un .db mentre s'hi està escrivint.

Com restaurar

# Des del .sql
sqlite3 nova-bd.db < hivernacle-20250615.sql

# Des del .db copiat
cp hivernacle-20250615.db hivernacle.db

Optimitzacions per a l'hort IoT

-- Mode WAL per a millor rendiment i seguretat
PRAGMA journal_mode=WAL;

-- Sync normal (millor rendiment amb WAL)
PRAGMA synchronous=NORMAL;

-- Incrementar cache
PRAGMA cache_size=-20000;  -- 20 MB

-- Indexar per a consultes de sensors
CREATE INDEX idx_sensor_ts ON sensors(sensor, ts);

🛠️ Exercici pràctic (30-40 min)

Crear una base de dades SQLite, omplir-la amb dades de sensors, practicar el backup amb .dump, provar consultes, i restaurar-les.

Pas 1: Instal·la SQLite i DB Browser (5 min)

sqlite3 --version
sudo apt update
sudo apt install -y sqlite3 sqlitebrowser

Pas 2: Crea la base de dades (10 min)

mkdir -p /home/pi/bernatlab/proves
cd /home/pi/bernatlab/proves

sqlite3 hivernacle.db <<EOF
CREATE TABLE sensors (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  sensor TEXT NOT NULL,
  valor REAL NOT NULL,
  ts DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_sensor_ts ON sensors(sensor, ts);
INSERT INTO sensors (sensor, valor) VALUES
  ('temperatura', 22.5),
  ('humitat', 65.0),
  ('llum', 850.0),
  ('temperatura', 23.0),
  ('humitat', 64.0);
SELECT * FROM sensors;
EOF

Pas 3: Practica consultes (5 min)

sqlite3 /home/pi/bernatlab/proves/hivernacle.db
.mode column
.headers on
SELECT * FROM sensors WHERE sensor = 'temperatura';
SELECT sensor, AVG(valor) FROM sensors GROUP BY sensor;
.quit

Pas 4: Fes un backup consistent (5 min)

sqlite3 /home/pi/bernatlab/proves/hivernacle.db .dump > \
  /home/pi/bernatlab/proves/hivernacle-backup-$(date +%Y%m%d).sql
ls -lh /home/pi/bernatlab/proves/

Pas 5: Simula un desastre i restaura (10 min)

rm /home/pi/bernatlab/proves/hivernacle.db
sqlite3 /home/pi/bernatlab/proves/hivernacle.db < \
  /home/pi/bernatlab/proves/hivernacle-backup-*.sql
sqlite3 /home/pi/bernatlab/proves/hivernacle.db "SELECT COUNT(*) FROM sensors;"

Pas 6: Accedeix des de Python (5 min)

cat > /home/pi/bernatlab/proves/insertar.py <<'PY'
import sqlite3

db = sqlite3.connect('/home/pi/bernatlab/proves/hivernacle.db')
cur = db.cursor()
cur.execute(
    "INSERT INTO sensors (sensor, valor) VALUES (?, ?)",
    ('temperatura', 22.7)
)
db.commit()
cur.execute("""
    SELECT * FROM sensors
    WHERE sensor = 'temperatura'
    ORDER BY ts DESC
    LIMIT 5
""")
for fila in cur.fetchall():
    print(fila)
db.close()
PY
python3 /home/pi/bernatlab/proves/insertar.py

Pas 7: Usa DB Browser per visualitzar

sqlite3 /home/pi/bernatlab/proves/hivernacle.db ".schema"

Resum ràpid

  1. SQLite = un sol fitxer .db.
  2. Límit = ~1 TB teòric, ~1 GB pràctic.
  3. GUI = DB Browser for SQLite.
  4. Backup = sqlite3 db.db .dump.
  5. Avantatge = no necessita servidor.
  6. Journaling = WAL.
  7. Extensions = .db, .sqlite, .sqlite3.
  8. NO adequat = 1000 usuaris concurrents.
